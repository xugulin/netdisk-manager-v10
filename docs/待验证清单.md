**本轮真机修复：**

1. 百度扫码后误判未登录 → `gettemplatevariable` 真机回 -6，增加 `/api/loginStatus` 回退通道；
2. 百度 pan 域 STOKEN 捕获（302 Location 的 `stoken=` 128 字符）—— 已实现捕获逻辑，但实测扫码会话仍为只读（与 V2 源码结论一致），**写操作需浏览器 Cookie 登录**；
3. 光鸭 multipart 业务 complete 偶发 `HTTP 410 code=128`，但文件实际已落地 → 改为以 `get_info_by_task_id` 为准。

**百度文件上传失败的真正原因（真机数据）：**

- 该账号容量接口返回 `total=2.21TB`、`used=9.94TB`（**已用超总容量**，`free` 字段异常地等于 total），
  即账号处于超容状态；建目录/重命名/删除/分享等元数据写操作全部成功，
  唯独文件落盘（`/api/create`，`isdir=0`）返回 `errno:-10`。
- 已排除客户端因素：precreate ✅、superfile2 分片上传 ✅（服务端返回 md5）、
  参数与 Python 参考实现逐字段一致。**清理网盘空间/续费 VIP 后即可复测文件上传**。
- 另一个已修复的真机 bug：`/api/filemetas` 对不存在路径返回 `errno:12`，
  需映射为「未找到」，否则 `ensure_dir` 在探测阶段就失败（已修）。

**百度写权限的已知限制与绕行：**

- 扫码登录（`qrbdusslogin`）拿到的是 passport 域 STOKEN，百度读接口只认 BDUSS、写接口认 BDUSS + pan 域 STOKEN ⇒ **扫码会话天然只读**（V2 源码 `桥/后端_百度.py:43` 同样结论）；
- 绕行：用浏览器 Cookie 登录（百度网盘网页版 F12 复制 Cookie → 软件「登录 → Cookie」/ `wp-cli login-cookie`）。V2 也是通过「内置浏览器补全会话」解决。
- 后续可做：GUI 内置网页登录（需 WebView，跨平台代价大，暂不纳入）。
