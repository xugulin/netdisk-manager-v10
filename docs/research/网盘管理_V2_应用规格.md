### 1.3 配置体系

1. 深拷贝硬编码 `默认配置`（`配置.py:51-127`）；

#### 2.2.5 上传 / 下载流程
**上传**（`网盘页面.py:1477-1497`）：

1. `QFileDialog.getOpenFileNames` 多选文件，或 `getExistingDirectory` 选文件夹；
2. 交给 `主窗口.传输页面().添加上传任务(实例标识, 本地路径, 当前目录)`；
3. 传输页把任务放入**本地任务队列**（`本地任务工作线程`，并发 4），不走跨盘引擎；
4. 立即切换到传输页并写日志；
5. 文件夹递归：远端根=`当前目录/文件夹名`，按相对路径建子目录（`传输页面.py:1230-1251`）；
6. 上传经 `上传守卫.上传`（若启用）→ 预检改名 / 失败绕过；
7. 同名覆盖：本地任务默认不覆盖（`覆盖=False`），由适配器行为决定；**待确认** UI 是否有冲突提示（未见专门弹窗）。

**下载**（`网盘页面.py:1499-1519`）：

1. 只取选中文件（跳过目录）；
2. 选择保存目录；
3. `添加下载任务(标识, 远端路径, 保存目录/文件名, 大小)`；
4. 本地任务工作线程并发 4；桥 `download` 支持多段/续传/保守模式；
5. 切到传输页。

**删除**：二次确认（列出前 5 个名字 + 总数），后台线程逐个 `delete`；网盘端通常进回收站；失败项汇总成一条 RuntimeError（`网盘页面.py:1558-1595`）。

**新建文件夹**：`QInputDialog` 输入名字，直接 `拼路径`，不校验非法字符（非法字符由后端命名规避/服务端报错处理）；后台线程。

**详情**：后台 `stat`，非模态 `QDialog`（`setModal(False)`）表单展示：名称/类型/大小/路径/修改时间/ID；关闭按钮（`网盘页面.py:68-101, 1637-1685`）。

**复制播放直链**：仅视频；后台 `取播放直链`；取 `url` 或 `直链` 字段写入剪贴板；失败弹错（`网盘页面.py:1608-1635`）。

**跨网盘直传**：打开 `跨盘直传对话框`，默认源=当前实例、源路径=当前目录；若选中文件则预填；确定后 `传输页.添加跨网盘传输`（`网盘页面.py:1521-1536`）。

## 3. 适配器契约与桥协议（最重要）
### 3.1 三层架构
```
Rust/PySide GUI（主进程）
  └─ 云盘适配器接口（v8_3/核心/适配器.py）
       └─ 子进程适配器（v8_3/核心/子进程客户端.py）
            ⇅ stdin/stdout 每行一个 JSON
       └─ 工作进程（v8_3/桥/工作进程.py）
            └─ 后端基类 + 后端_{百度,夸克,光鸭,假}
                 ⇅ sys.path[0] = 适配器项目根
            └─ 适配器/{百度,光鸭,夸克}网盘适配器/核心/
```

**为什么必须子进程**：三家上游适配器的顶层包都叫 `核心`/`界面`，同进程 import 会互相覆盖；桥进程把单个适配器项目根插入 `sys.path[0]`，实现隔离（`工作进程.py:55-58`）。
### 3.2 适配器规格 / 多实例
`适配器规格` dataclass（`核心/适配器.py:73-190`）：

| 字段 | 类型/默认 | 说明 |
|---|---|---|
| `类型` | `网盘类型` | 决定后端：baidu/guangya/quark/fake |
| `名称` | str=`""` → 类型中文名 | 显示名 |
| `项目根` | str=`""` | 适配器目录，可为相对 |
| `Python解释器` | str=`""` → `sys.executable` | 桥解释器 |
| `线程数` | int=`8`（配置默认 12） | 桥传输池大小 |
| `已启用` | bool=`True` | |
| `标识` | str=`""` → `类型.value` | **多实例唯一键** |
| `额外参数` | dict | `{"下载分段": int, "下载阈值": int}` |

关键属性：

- `路径`：相对路径**按项目根解析**（不是进程 cwd；桥 cwd 是 `v8_3/桥`，曾导致 `ModuleNotFoundError: 核心`），`适配器.py:109-130`。
- `数据目录` = `路径/数据`；`凭证文件` 按类型映射：百度 `数据/会话.json`、光鸭 `数据/令牌.json`、夸克 `数据/凭证.json`、假 `数据/登录.json`（`适配器.py:136-154`）。
- `校验()`：目录存在、`核心/` 存在；`校验目录()` 静态检查；`启动适配器GUI()` 启动上游 `启动.py`。

**标识生成**（`适配器.py:53-70`）：

- 基础 = 类型值（`baidu`），若已用则 `baidu_2`、`baidu_3`…；
- `规范化标识`：小写、空白/斜杠转 `_`、仅保留 `[0-9a-z_中文-]`、去首尾 `_-`；
- 配置加载时若标识冲突，自动再生成（`配置.py:230-235`）；
- 查找实例支持 标识 / 名称 / 类型 / 类型中文名（`配置.py:248-267`）。

**多实例规则**：

1. `标识` 是全局键，贯穿配置、界面导航、引擎、任务库、敏感词库、守卫表；
2. `类型` 只决定桥后端；同类型多账号必须**各自独立的适配器目录**（凭证隔离）；
3. 新增第二账号时 `复制适配器项目` 复制源码但**排除 `数据/`、`__pycache__`、`.git`、`*.pyc`**（`配置.py:373-401`）；
4. 删除实例只从配置移除，不删适配器目录与登录数据（`主窗口.py:641-643`）。
### 3.3 桥进程启动与传输层
启动（`子进程客户端.py:85-130`）：

| 项 | 值 |
|---|---|
| 命令 | `{Python解释器} -u {v8_3/桥/工作进程.py} --adapter {类型} --project-root {绝对路径} --threads {N}` |
| cwd | `v8_3/桥` |
| 环境 | 复制父环境；`PYTHONPATH` 前插项目根（让桥能 import `v8_3.敏感词.命名规避`）；`PYTHONIOENCODING=utf-8`、`PYTHONUNBUFFERED=1`、`PYTHONUTF8=1`；`V8_3_DL_SEGMENTS`、`V8_3_DL_THRESHOLD` |
| 管道 | stdin/stdout/stderr 文本、UTF-8、行缓冲 |
| 读线程 | stdout 一个、stderr 一个（daemon） |
| 握手 | `ping`，超时 30 秒；失败即启动失败 |
| 关闭 | `close`（10s）→ terminate → 5s → kill → 关流 → 失败所有等待 |

**请求帧**（`子进程客户端.py:176-178`）：

```json
{"id": 1, "cmd": "list", "params": {"path": "/"}}
```

- `id` 由 `itertools.count(1)` 单调递增；
- 紧凑 JSON（`ensure_ascii=False, separators=(",", ":")`）；
- 每个请求一个 Future，按 `id` 回填；**允许并发请求**（由桥线程池执行）。

**响应帧**（`工作进程.py:100-124`）：

```json
{"id": 1, "ok": true,  "result": ...}
{"id": 1, "ok": false, "error": {"type": "PermissionError", "message": "..."}}
```

**事件帧**（无 `id`，有 `event`；`工作进程.py:83-96`）：

```json
{"event":"progress","task_id":"t1","phase":"download","current":123,"total":456}
{"event":"log","level":"info","message":"..."}
```

客户端事件处理：`progress` 按 `task_id` 找进度回调并调用 `(phase, current, total)`；`log` 走日志回调；未知事件忽略（`子进程客户端.py:238-251`）。

**超时/错误语义**：

| 操作 | 超时 |
|---|---|
| `调用()` 默认 | 120 秒 |
| `ping` | 30 秒 |
| `upload` / `download` | **None（不限时）** |
| `login_qr_start` | 60 秒 |
| `login_qr_wait` | 用户给 180 秒 + 120 秒（桥内可能稍后落凭证） |
| `login_cookie` / `sms_verify` / `token` / `password` / `email` | 180 秒 |
| `sms_send` / `logout` / `write_probe` | 120 / 60 / 60 秒 |
| `pause_task` / `resume_task` | 15 秒 |
| `close` | 10 秒 |

- 超时抛 `适配器错误("适配器调用超时…")`；
- 进程退出/EOF → `失败所有等待("适配器输出流结束")`，所有挂起 Future 收 `适配器错误`；
- `error.type == "未登录"` 才映射 `认证错误`；桥实际抛 Python 异常类名（如 `PermissionError`），因此该分支**基本不会命中**（`子进程客户端.py:212-222`，待确认是否为有意取舍）；
- 桥 stderr 由客户端按行转日志：含 `Traceback/Error/错误/失败` 判为警告，否则信息。

**桥内并发**（`工作进程.py:34-58, 258-278`）：

- 传输池：`ThreadPoolExecutor(max_workers=--threads)`；
- 登录池：固定 2 线程，`login_*` 与 `auth_caps` 走这里，避免扫码阻塞几分钟占满传输线程；
- 主线程逐行读 stdin 并 `submit`；
- `pause_task`/`resume_task` 通过 `_停止表[task_id] = Event`；上传/下载进度回调调用 `_检查停止`，被置位时在**桥进程内部**抛 `RuntimeError`，从而安全停下并保留断点（`工作进程.py:247-254`）；
- 停止粒度：任务级；`resume_task` 的 `task_id="*"` 清空全部。

### 3.8 对 Rust 的接口建议
1. **保留 JSON 行协议作为过渡层**：Rust 侧实现一个 `BridgeClient`（spawn + 读两线程 + id→Promise/Sender + 超时表），即可复用全部 Python 后端；这比一次重写三家鉴权现实得多。
2. **协议稳定面**：`id/cmd/params`、`ok/result/error`、`event/task_id/phase/current/total`。Rust 内部可用 serde 枚举，但对外 JSON 字段名不要改。
3. **必须保留的语义**：`upload/download` 不限时、进度回调可触发“安全暂停”、登录独立并发、实例标识贯穿。
4. **建议新增**（若产品需要）：`rename/move/copy/share/search`。V2 没有；桥后端上游其实有实现（百度 `管理接口.移动/重命名`，夸克 `文件接口.移动/重命名`，三家 `分享接口.创建分享`），但桥未接。
5. **错误模型**：统一 `error_type` 枚举（未登录/权限/未找到/冲突/限流/服务端/网络/取消/暂停），不要让 Rust 解析中文文案；V2 的中文关键词匹配是历史包袱。
6. **并发**：桥进程每实例一个，池大小=配置线程数；Rust 若要单进程原生实现，需自己保证同实例串行化（尤其 ID 型网盘的目录创建）。

### 5.2 调度模型（四层并发）
| 层 | 机制 | 位置 |
|---|---|---|
| 源扫描 | 独立 8 线程池，逐层并行 BFS 列目录；目录不存在先重试 4 次×1.5s（最终一致性） | `传输引擎.py:414-453, 485-509` |
| 目标预检 | `min(8, 父目录数)` 并发列父目录，消除 N+1 | `:730-751` |
| 文件任务 | `ThreadPoolExecutor(max_workers=32)` + `并发控制器` 可调许可 | `:341-354, 791` |
| 自适应 | 独立调优线程每 3s 采样；`吞吐自适应器` 最少 4s 调一次 | `:372-390`；`并发.py:60-107` |
| 兜底 | 信号量闸门，默认 1；排队超时 1800s | `:204, 944-953` |

**初始并发**（`_计算并发` 1434-1444）：

- 显式 `并发>0`：`clamp(1..32, 并发)`；
- 全小文件：`小文件并发`（16）；
- 全大文件：`大文件并发`（3）；
- 混合：`大文件并发 + max(1, 小文件数//4)`；
- AI 可用且未显式指定：用 AI 建议值覆盖（`320-322`）。

**自适应算法**（`并发.py:73-107`，每 ≥4s）：

- 失败增量 >0：上限 − max(1, 失败增量)，下限 1；
- 吞吐 > 上次 ×1.15 且队列有货：上限 +1；
- 吞吐 < 上次 ×0.6 且上限 >2：上限 −1；
- 否则不变；上限夹在 1..32。
### 5.3 生命周期
批次级（`传输` 197-254）：

1. 清停止标记、重建兜底闸门、清理 6 小时前旧中转（保留本批次）；
2. `批次开始` 事件；
3. 扫描源（单文件直接返回；目录递归 BFS）；
4. 为每个文件建任务（任务 ID=`{batch}_{i:06d}`），计算目标路径（相对路径映射）；
5. 可选 AI 策略；
6. 初始化统计、保存批次/任务（状态 running）；
7. `_调度`：
   - 过滤等待任务，AI 优先级排序；
   - **目标预检查**（同名语义见下）；
   - 按目标父目录深度**串行** `ensure_dir`，避免 ID 型网盘并发建目录；
   - 计算初始并发，创建控制器/自适应器；
   - 提交全部任务到 32 线程池；每个任务先 `控制器.获取()`，再 `等待可运行`（暂停则等）；
   - `as_completed` 收尾，异常任务记失败；
   - `_结束批次`：状态 `failed`/`cancelled`/`done`，写库，发 `批次完成`。

单任务（`_执行文件任务_主流程` 824-917）：

```
重试循环 [0..重试次数]：
  覆盖模式：先 stat + delete 旧目标
  downloading：预留磁盘额度 → 下载到缓存 → 校验大小 → 保存
  ensure_dir(目标目录)
  uploading：守卫.上传 或 目标.上传 → 记录实际目标名 → 保存
  完成：状态 done，发"任务完成"
异常分类：
  任务暂停 → paused，统计.已暂停+1，保留分片
  任务取消 → cancelled
  其它 → 记录错误；未耗尽则按退避 sleep 后 continue；耗尽 → failed → 兜底 → 仍失败则发"任务失败"
```
### 5.4 暂停 / 继续 / 取消
| 操作 | 语义 |
|---|---|
| `全部暂停` | 设置全局暂停 Event；**排队任务不再开跑，已在跑的不立即打断** |
| `全部继续` | 清全局暂停 + 清所有任务停止位 |
| `暂停任务` | 加入 `_暂停任务集`；若在跑，桥 `pause_task` 置位，下一次进度回调抛 `任务暂停`；排队任务在 `等待可运行` 处等待 |
| `继续任务` | 从集合移除；桥 `resume_task`；任务从断点续传 |
| 取消 | 通过批次级 `取消事件`（UI 的“停止”）；运行中任务在下一次检查点抛 `任务取消`；已暂停任务也会被取消 |
| 粒度 | 任务级暂停；批次级取消（没有“取消单个任务”的桥命令，UI 的“移出列表”只清台账） |
| 暂停保留 | 分片 `.v8_3part*`、续传状态 `.v8_3resume.json`、半成品文件均保留；`结束时间=0` |
| 取消/失败清理 | 默认删中转；`缓存.保留失败文件=true` 时保留（取消也按下述逻辑清理） |

暂停竞态兜底：异常文本可能是桥的“任务已被用户暂停/取消”，只要暂停标记仍在，就按 `paused` 处理，不记失败（`:869-882`）。
### 5.5 进度与速率
- 桥进度 → 引擎 `_更新进度(方向, 阶段, 当前, 总量)`：
  - download：`下载字节=max(下载字节,当前)`，`已传输=下载字节`；
  - upload：`上传字节=max(上传字节,当前)`，`已传输=max(已传输,上传字节)`；

  - 顺带 `_检查暂停` —— 这是暂停的安全点。
- 统计平均速度只在批次结束/结账时刷新；界面 1 秒定时器用台账字节差算瞬时速度/剩余时间。
- 任务事件 `to_dict`：`{"type","message","task"?,"stats"?,"data"?}`。
### 5.6 跨盘直传流程与四个已知问题
**流程**：源适配器 `download` → 本地中转文件 → 目标适配器 `upload`。不是服务端到服务端；所谓“直传”指不经 Alist/WebDAV（引擎 docstring 1-10；`_执行一次` 995-1090）。

缓存路径：`{缓存根}/{批次ID}/{任务ID}{源后缀}`（`_缓存路径` 1180-1185）。

**四个已知问题/坑**（源码与审计文档可证）：

1. **可见性延迟**：源盘刚上传的文件 1–3 秒内 `stat/list` 查不到（ID 型网盘最终一致性），跨盘立即开始会报“源路径不存在”。对策：源根 `_确认源存在` 重试 4×1.5s；后端 `list` 上传后 `确认可见` 轮询 5×1.2s；夸克 `_找子项` 不用 10s 缓存（`传输引擎.py:485-509`；`后端_夸克.py:302-309`；`后端_基类.py:361-396`）。
2. **同名/同名目录冲突**：目标预检按父目录聚合，但同名语义分五类（覆盖开/同名目录/源大小未知/大小一致/大小不同）；同名目录直接跳过、大小不同不静默覆盖，必须勾“覆盖”。（`传输引擎.py:759-782`）
3. **ID 型网盘并发建目录竞态**：8 线程同时往未创建目录上传会 `file is doloading[同名冲突]`；对策：目录按深度串行 `ensure_dir` + 后端 `_路径锁` + 内存去重集（`传输引擎.py:311-317, 1187-1195`；`后端_夸克.py:316-358`）。
4. **直链签名 URL 失效/限流/零字节断流**：多段/单连接直链失败后，若本次“搬动过字节”则上抛保留断点；若“零字节进展”则重取直链或回退适配器原生下载（百度/夸克/光鸭各自实现）；最终仍失败才走“源→本地→目标”保守兜底（`后端_百度.py:936-952`；`后端_夸克.py:657-694`；`后端_光鸭.py:1226-1238`；`传输引擎.py:921-993`）。

另有两个实现级坑（不属“四个”但影响重写）：

- **多段下载磁盘占用是 2 倍**（分片 + 合并副本 + 原子替换），引擎对 ≥8 MiB 文件按 2× 预留（`传输引擎.py:1023-1031`）；实测 12 MiB 峰值 24 MiB。
- **上传侧无断点续传**（V2 明确未做；大文件上传中断需整文件重传）。Rust 若要补，需要后端分片会话协议，不能只靠本地 `Range`。
### 5.7 失败处理与重试
`_是瞬时错误`（468-475）：

- 认证/权限/参数/不存在/名称不可用/敏感 → **不重试**；
- 其它命中 `瞬时错误关键词`（服务端暂不可用类）→ 瞬时。

`_退避秒`（478-483）：

- 瞬时：`min(60, 3 * 2^尝试)` → 3/6/12/24/48/60s；
- 普通：`min(30, 1.5^尝试)` → 1.5/2.25/3.375/5.06…s。

失败后：

1. 若 `断点续传` 开：保留分片并记录残留字节；否则清中转；
2. 退避 sleep，继续下一次；
3. 耗尽 → `failed`；
4. 若 `失败兜底` 且未取消 → `_兜底本地中转`：清中转、跳过直链、`保守=True` 原生下载、串行闸门、重新上传；成功改判 `done`，统计 `兜底次数/兜底成功` 增加；
5. 兜底失败 → 结账失败，发 `任务失败`，可选 AI 诊断。
### 5.8 临时缓存管理
| 规则 | 值 |
|---|---|
| 目录 | 配置 `缓存.目录`；空则 `/dev/shm/v8_3_中转` → temp；无写权限则 mkdtemp |
| 单次上限 | `传输.暂存上限GB`；0=自动 `max(256MiB, min(4GiB, (free-余量)/4))` |
| 系统余量 | `传输.磁盘余量GB`，默认 1 GiB |
| 预留 | 下载前按文件大小预留；≥8 MiB 按 2×；单文件超上限放行并日志 |
| 等待 | 额度不足最多等 600s，每 5s 日志；超时报错而不是写满磁盘 |
| 归还 | 任务成功/失败/取消后 `finally` 立即归还；默认删中转 |
| 旧残留 | 批次开始清理 6 小时前批次目录（保留当前批次） |
| 后缀 | `.v8_3part*`（分片）、`.v8_3resume.json`（续传状态）、`.v8_3merge`（合并中间件） |

### 5.9 任务数据库与恢复
`核心/任务数据库.py`（194 行），SQLite WAL + `synchronous=NORMAL` + 30s timeout + 单连接 + RLock。

```sql
CREATE TABLE batches(
  batch_id TEXT PRIMARY KEY,
  source_cloud TEXT NOT NULL,
  source_path TEXT NOT NULL,
  target_cloud TEXT NOT NULL,
  target_path TEXT NOT NULL,
  config_json TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'running',   -- running/done/failed/cancelled
  created_at REAL NOT NULL,
  updated_at REAL NOT NULL
);
CREATE TABLE tasks(
  task_id TEXT PRIMARY KEY,
  batch_id TEXT NOT NULL,
  source_path TEXT NOT NULL,
  target_path TEXT NOT NULL,
  size INTEGER NOT NULL DEFAULT 0,
  status TEXT NOT NULL,
  error TEXT NOT NULL DEFAULT '',
  retries INTEGER NOT NULL DEFAULT 0,
  done_bytes INTEGER NOT NULL DEFAULT 0,
  download_bytes INTEGER NOT NULL DEFAULT 0,
  upload_bytes INTEGER NOT NULL DEFAULT 0,
  local_cache TEXT NOT NULL DEFAULT '',
  started_at REAL NOT NULL DEFAULT 0,
  finished_at REAL NOT NULL DEFAULT 0,
  stage TEXT NOT NULL DEFAULT '',
  skip_reason TEXT NOT NULL DEFAULT ''
);
CREATE INDEX idx_tasks_batch ON tasks(batch_id, status);
```

接口：`保存批次`（UPSERT，仅更新状态/更新时间）、`更新批次状态`、`读取批次`（`config_json` 反序列化为 `config`）、`未完成批次`（`status != 'done'`，按 updated_at 倒序）、`删除批次`（先删任务）、`保存任务`（UPSERT，**不更新 source/target/size/batch_id**）、`批量保存任务`（逐条）、`读取任务`（按 task_id 排序，源/目标网盘留空由调用方回填）、`关闭`。

**恢复批次**（`传输引擎.py:256-291`）：

1. 读批次；不存在抛 `KeyError`，引擎无库抛 `RuntimeError`；
2. `传输请求.from_config(config, batch_id)`；
3. 读任务，按源/目标回填；
4. 状态映射：`等待/枚举/下载/上传/失败/已取消` → `等待`；`跳过/完成` 保留；
5. 重新调度，已完成的文件不重传。

**重启语义**：只有 `恢复批次` 是显式操作（传输页“♻ 恢复批次…”）；程序启动**不会自动恢复**。Rust 版建议提供“启动时自动恢复未完成批次”的开关。
### 5.10 Rust 复刻行为清单（含边界）
| # | 行为 | 边界/必测 |
|---|---|---|
| 1 | 源扫描 BFS 并行 8，目录不存在重试 4×1.5s | 空目录、权限错误、根路径是文件、递归关闭且源是目录 |
| 2 | 目标预检按父目录聚合，同名五分支 | 同名目录、大小 0、大小不同、覆盖开 |
| 3 | 目标目录串行创建，按深度排序 | 多级新目录、并发同目录 |
| 4 | 初始并发公式 + 自适应上下限 | 全小/全大/混合/显式 0/64/负数 |
| 5 | 重试退避与“非瞬时错误不重试” | 认证失败、404、名称不可用 |

### 6.2 词条模型与匹配
词条字段：`敏感词`、`网盘名称`、`发现时间`、`最后一次成功安全词`、`最后一次成功时间`、`已失效安全词`（dict）、`来源`。**没有**独立分类/级别/正则/启用字段；启用是全局/按网盘开关，不是词级。

匹配算法（`:432-506`）：

- 首选 `pyahocorasick`；缺失回退纯 Python AC 自动机（含 fail 指针），功能等价、较慢；
- **区分大小写、纯子串匹配**；不做繁简/全半角/分隔符/拼音归一化；
- `ac.iter(文本)` → `{'敏感词','起','止'}` → 按 `(起, -长度)` 排序 → 去掉被外层完全包含的内层命中；
- `匹配敏感词` 返回最长命中；`扫描所有敏感词` 返回全部；
- 中文分段正则 `[\u4e00-\u9fff\u3400-\u4dbf]+`；
- 拼音只用于**生成安全词**：`生成安全词` 从右往左找第一个中文字换成拼音；`全部转拼音` 整串转换；缺 `pypinyin` 时降级为 `u{ord:04x}`（仍可用但不可读）；
- 候选安全词：递归生成（最多 `len*2+5` 次），过滤 `已失效安全词`，追加全拼候选（`:508-527`）。
### 6.3 命名规避
`敏感词/命名规避.py`（125 行）。**与敏感词是两回事**：这里处理目标盘字符集限制。

| 网盘 | 限制 |
|---|---|
| `baidu` | 非法字符：反斜杠、斜杠、冒号、星号、问号、双引号、尖括号、竖线；禁止不可见字符；禁止星平面（emoji） |
| `quark` / `guangya` | 实测支持这些字符与 emoji，**不改名** |
| 未知 | 无限制，不擅自改名 |

规避策略（`:87-125`）：

- 非法字符 → 全角等价：`＼ ／ ： ＊ ？ ＂ ＜ ＞ ｜`；
- 控制字符（`\x00-\x1f\x7f-\x9f`）→ 单个空格，连续折叠；
- 星平面（`ord>0xFFFF`）→ 移除；
- 名字被清空 → `未命名_{md5(原名)[:4]}`，保留扩展名；
- 使用 `PurePosixPath` 取文件名（Windows 上 `Path("a:b.txt")` 会误判盘符，真机 CI 踩过）；
- 返回 `(新名称, 说明)`；`需要规避` 返回 `(bool, 原因)`。

触发点三处：

1. 桥后端 `upload` 内 `规范命名(网盘, 名称)`，结果以 `返回["改名信息"]` 回传（策略 `命名规避`）；
2. 服务端实际落盘名与请求名不同（策略 `服务端改名`）；
3. 上传守卫在预检/绕过改名时写 `改名记录`。
### 6.4 上传守卫
`敏感词/上传守卫.py`（638 行）。两类对象：

**`敏感词绕过器`**（与传输层解耦）：

- `预检(目标路径, 大小)`：扫文件名 → 用已有安全词批量替换 → 写改名记录 + 统计 `预检命中`；返回 `(新路径, 是否改名)`；
- `尝试绕过(目标路径, data)`：P1 已知词批量替换 → P2 单段探测 + 瘦身 → P3 组合（相邻 2–4 段，候选全拼）→ P4 全中文化保底；
- 瘦身：高频词优先 → 二分定位 → 2–6 字窗口搜索 → 逐字去尾/去首；最多 30 次 PUT；窗口 2–6；
- 每次探测写 `敏感词探测历史`；成功写 `记录安全词成功` + 改名记录；失败记失效；
- `P2每段最多候选=2`、`P3最大组合长度=4`、`P3每组合最多候选=1`。

**`上传守卫`**（适配器包装）：

```python
守卫 = 上传守卫(适配器, 实例标识, 词库,
               启用=..., 自动改名=..., 最大绕过字节=32MiB,
               中转目录=..., 日志=...)
结果 = 守卫.上传(local_path, remote_dir, 名称=..., 进度=..., 任务ID=...)
```

| 项 | 语义 |
|---|---|
| `生效` | `启用 && 词库 != None && 绕过器` |
| `预检名称` | 未启用/未开自动改名 → 原名；命中 → 返回新名 + 是否改名 + 原名 |
| `上传` | 先预检；调适配器上传；若后端返回 `改名信息` 也写改名记录；捕获异常后若 `是拦截错误` 且大小 ≤32 MiB → 读入内存 → 探测绕过；成功返回 `{name,path,size,bytes,绕过:true,原名称}`；失败原样抛 |
| `拦截关键词` | 405/403/451、敏感/违规/禁止/非法/审核/拦截、sensitive/forbidden/blocked/risk/banned、名称不可用/文件名不可用/名称非法/名称无效/请更换后重试/更换名字/名称包含/命名不符合、invalid name/not allowed 等（`:456-465`） |
| 用户交互 | **没有弹窗选择“拦截/改名/跳过/放行”**；完全自动：能改名就改名上传，超过 32MiB 或无法绕过则原样失败，由传输页显示错误。想“跳过”只能在传输页移出/停止；想“放行”需关自动改名或按网盘关敏感词 |
| 统计 | `预检改名/预检成功/绕过尝试/绕过成功/绕过跳过_过大/绕过失败`；敏感词页底部显示 |

**与传输引擎接口**：引擎不直接 import 守卫；`传输引擎(守卫表={标识: 守卫})`，上传时按 `任务.目标网盘` 取守卫；守卫不可用则走原适配器（`传输引擎.py:1068-1074`）。本地上传任务也通过 `取守卫` 注入（`传输页面.py:1303-1305`）。

**Rust 重写建议**：

- 表结构照抄，但把 `敏感词树` 的置信度学习做成可选（V2 实际很少用）；
- 匹配用 `aho-corasick` crate；词库按实例缓存，变更即失效；
- 守卫接口保持“`upload` 包装 + 返回改名信息”，不要侵入传输引擎；
- 交互建议补一个策略枚举（自动改名/拦截/跳过/放行），V2 是硬编码自动。
