### 1.4 `PLAN.md` 对协议/架构的结论（提炼）

1. 认证：原适配器 OAuth2 设备码→token；夸克 CAS 扫码→`service_ticket`→Cookie，**无 refresh**，过期只能重登（`PLAN.md:87-121`、`核心/认证/登录服务.py:10-19`）。
2. 两个登录通道：扫码（推荐）、手动 Cookie（最可靠，自带 `__puus`）；短信删除（`PLAN.md:832-842`、`登录服务.py:3-8`）。
3. 上传真实流程：`file/upload/pre`→`file/update/hash`→每片 `file/upload/auth`+OSS PUT→合并授权+OSS POST→`file/upload/finish`；4MB 分片、≤5MB 单 PUT；`X-Oss-Hash-Ctx` 第 2 片起强制（`PLAN.md:509-533`）。
4. 增量 SHA1 离线 4/4 验证正确；4MB=65536×64，不需要 padding；`GET config` 的 `allow_ccp_hash_update:false` 是红鲱鱼（`PLAN.md:517-531`）。
5. `GET capacity` 实测 404，`file/capacity`、`member/capacity` 也 404；账号/容量/会员走 `GET member`（`认证服务.py:5-14`）。
6. `file/delete` 事故：`fid_list`+`current_dir_fid="0"` 被按「删除整目录」模式处理，清空根目录；正确是 `action_type=2,filelist,exclude_fids`（`PLAN.md:552-572`）。
7. 下载必须 `__puus`，缺失 403 `RequestDeniedByCallback/auth miss`；扫码不下发，登录后 `member` 补发（`PLAN.md:576-579`）。
8. `file/search` 用 `q` 不是 `keyword`；`file/tree` 用 `max_depth`；回收站恢复 `recover` 且必须 `select_mode`（`PLAN.md:580-583`）。
9. 分享两套 ID：32 位 hex `share_id`（管理/取消）与 URL slug（访问/转存），不相等（`PLAN.md:584-585`）。
10. 夸克常用 HTTP 404/400 + JSON body 表达业务错误（如 41017），先解析 JSON 再 `raise_for_status`（`PLAN.md:586-587`）。
11. 列表有秒级延迟；失败分片上传会留下幽灵文件（`PLAN.md:538-539`、`:588`）。
12. 凭证过期只取 `__pus/__puus/__kps/__uid/__ktd` 的最小 expires；对全部 Cookie 取 min 会被 `ctoken`（约 10 分钟）误判（`PLAN.md:589-591`）。
13. 能力边界：文件浏览/上传/下载/分享/账号/扫码/手动 Cookie；不做离线下载、回收站 UI、上传记录、短信、埋点（`PLAN.md:842`）。

### 2.4 URL 拼接、编码、头校验

- `_拼接地址`：右 `rstrip("/")` + 左 `lstrip("/")`，避免 `.../clouddrivefile/sort`（`:74-91`）。
- `_安全URL`：仅当 URL 含非 ASCII 时对 path/query/fragment 百分号编码，scheme/netloc 不动；异常原样返回（`:94-113`）。
- `_校验请求头`：header value 必须 ASCII，否则 `ValueError`；`None` 丢弃（`:116-132`）。
- `请求()` 顺序：公共头 → 调用方 headers 覆盖 → ASCII 校验 → 公共 query（`dict(公共查询参数)`+`__dt`+`__t`+调用方 params 覆盖）→ URL 拼接/编码 → `_执行带重试`（`:315-355`）。日志打印完整 params/json（`:348`）。

### 2.5 响应判定与错误包装

成功 ⇔ HTTP 200 且 `JSON.status == 200`（整数/可转）且 `code ∈ (0,None)`（`:45-49`、`:276-313`）。流程（`:357-401`）：

1. 收到响应立即 `_捕获刷新Cookie`：从 `Set-Cookie` 取 `__puus` 合并进内存 Cookie（`:242-261`）。
2. `raw=True` 直接返回，不校验（`:360-361`）。
3. HTTP ≥400：先解析 JSON；若 dict 含 `code` 或 `message`，抛 `接口错误(message, 状态码=HTTP, 业务码=body.code, 请求ID=body.req_id 或 x-request-id)`（`:368-382`）。例子：转存自己的分享 → 404 + `{"code":41017,"message":"用户禁止转存自己的分享"}`（`:364-366`）。
4. `需要认证` 且 HTTP∈(401,403)：抛 `接口错误("登录已过期或 Cookie 无效，请重新登录", 状态码, 请求ID)`（`:384-388`）。
5. 其他 HTTP ≥400 走 `raise_for_status()`，抛 `httpx.HTTPStatusError`，**未包装**（`:390`）。
6. JSON 解析失败：`接口错误("响应不是合法 JSON: <前200字>")`（`:392-398`）。
7. `_检查业务状态`：`status` 缺失跳过；可转 int 用该值，`"ok"/"success"` 视为 200，其余不可转视为 -1；`status != 200` 抛错（业务码=status）；`code` 非 None 且非 0 抛错（业务码=code），`允许业务码` 白名单可放过（`:276-313`）。

`接口错误` 字段：`消息`、`状态码`(HTTP)、`业务码`(status/code)、`请求ID`（`:182-194`）。参考实现 QuarkPan 只判 `status=='error'`/`code!=0`，`{"status":400}` 会被当成功；本项目显式要求 `status==200`（`:45-49`、`PLAN.md:944`）。

**第 3 步：轮询扫码状态**

响应关键路径：`status`、`message`、`data.members.service_ticket`（`:175-178`）。完整映射（`:150-192`）：

| 条件 | 业务状态 | 行为/提示原文 |
|---|---|---|
| `int(status)==2000000` 且 ticket 非空 | 成功 | 返回 `{"状态":"成功","消息":message,"service_ticket":ticket}`；日志「扫码成功，已取得 service_ticket」 |

| HTTP 非 200 | 等待 | `{"状态":"等待","消息":"HTTP <code>"}`，**不失败** |

### 4.10 路径解析（完整）

**fid 体系**：没有「完整路径→fid」官方接口，必须逐级列目录。每项有 `fid`/`pdir_fid`；根 `"0"`；分享内部 `pdir_fid` 也用 `"0"`。没有 fid→完整路径 的反向能力。

`解析(路径, 当前目录ID)` 规则（`路径解析.py:79-114`）：

- 输入 `""`、`"/"`、`"."` → `(当前目录ID 或 "0", True)`。
- 以 `/` 开头从根 `"0"`；否则从 `当前目录ID`。
- 按 `/` 切段、忽略空段；`.` 跳过。
- `..` 的行为特殊：绝对路径重置到 `当前目录ID`（不是根！），相对路径重置到 `"0"`；代码 `当前 = str(当前目录ID or "0") if 绝对 else "0"`（`:97`）。不是标准文件系统语义。
- 每段在当前目录名字索引查；不存在抛 `接口错误("路径不存在：<当前路径>/<段>（在 fid=<当前> 下未找到）")`（`:101-105`）。
- 命中后更新 fid/是否目录/当前路径；若命中文件但路径还有后续段，**立即返回该文件 fid+False**，不报错（`:110-112`）；`取目录ID` 会抛 `不是目录：<路径>`（`:116-121`）。
- 最终返回 `(fid, 是否目录)`；`取目录ID` 只接受目录；`确保目录ID` 逐级创建（见下）。

缓存（`:52-75`）：`dict[目录fid, dict[name,条目]]`；按目录缓存一次 `file/sort`（`pageSize=200`）；空结果 `sleep(1.5)` 再查一次再缓存（注释：`file/sort` 秒级延迟，刚删除后可能瞬时空页，`:55-64`）；同名只保留**第一个**（`:68-75`）；`清空缓存(目录ID=None)` 指定清一个/全清（`:43-47`）。

`确保目录ID`（`:123-146`）：逐级解析；不存在则 `创建文件夹` 继续；命中文件抛 `路径中 '<段>' 是文件，不能作为目录`；创建未返回 fid 抛错；最后清空全部缓存。`取真实名称(fid)` 只列根 `pageSize=2000`，不是递归反查（`:150-157`）。`列名称(目录ID)` 走缓存（`:159-161`）。便捷 `解析路径(网络,路径,当前目录ID)` 每次新建解析器、无缓存复用（`:164-167`）。

**Rust 注意**：缓存无 TTL/失效通知；创建/删除/移动/重命名/上传完成后必须显式清缓存；`确保目录ID` 末尾全清是粗暴但安全的策略。

3. `POST share/password` body `{"share_id":"..."}` → `data` 含 `share_url/passcode/pwd_id`（`:149-160`）。

单文件分享服务端**忽略自定义 title**，用文件名；创建响应、详情、列表三处 title 都等于文件名（`分享对话框.py:59-65`，实测）。列表接口**不返回 `passcode`**，提取码只能逐条 `share/password` 查（`分享页.py:374-410`、`字段映射.py:242`）。

**分享列表**：GET `share/mypage/detail`（base `drive-pc`）参数 `_page=1,_size=50,_order_field=created_at,_order_type=desc,_fetch_total=1,_fetch_notify_follow=1`（`分享接口.py:164-190`）。返回 `data.list`、`metadata._total`；列表项实测字段 `share_id`、`pwd_id`、`share_url`、`title`、`status`、`first_fid`、`created_at`、`updated_at`、`expired_at`、`file_num`（`分享页.py:257-261`），时间戳毫秒；`status` 展示 1 正常/2 已过期/3 已取消（`字段映射.py:102`）。UI 传 `page=0`，API 内部 `max(1,page)` 纠正。

**取消分享（静默 no-op 坑）**：正确 `POST share/delete` body `{"share_ids":["<32位hex>",...]}`（`分享接口.py:238-240`）。错误形态（A/B 实测，`:215-223`）：`{"share_id":"<hex>"}` 返回 `{"status":200,"code":0,"message":"ok"}` 但**什么都没删**；`{"share_id":["<hex>"]}` → HTTP 500 `inner error`。因会假成功，`取消分享(校验=True)` 默认删除后回查列表：最多 4 次、每次 1.5s，确认 `share_id` 是否仍存活；返回每项 `{"share_id","结果","已删除":bool}`（`:244-262`）。`_存活的分享ID` 最多 3 页×100（`:192-208`）。

**解析/生成**：支持 `https://pan.quark.cn/s/<slug>`、带 `密码：1234`、`quark://share/<slug>`；正则 `https?://pan\.quark\.cn/s/([0-9a-zA-Z]+)`、`quark://share/([0-9a-zA-Z]+)`、提取码 `(?:密码|提取码|访问码|code)[：: ]?\s*([0-9a-zA-Z]{4})`；兜底 8 位以上字母数字；无法识别抛 `接口错误("无法识别的分享链接：...")`（`:266-299`）。生成 `https://pan.quark.cn/s/<id>`（`:301-304`）。

**转存（三步，必须用分享域名 `https://drive.quark.cn/1/clouddrive`，仍带公共 query）**

1. `POST share/sharepage/token` body `{"pwd_id":"<slug>","passcode":"<code 或 空>","support_visit_limit_private_share":true}` → `data.stoken`；取不到抛 `未取到 stoken（提取码可能不正确）：...`（`:317-334`）。
2. `GET share/sharepage/detail` 参数 `pwd_id,stoken,pdir_fid=0,force=0,_page=1,_size=50,_fetch_banner=1,_fetch_share=1,_fetch_total=1,_sort=file_type:asc,file_name:asc`；返回 `data.list/total/share`（`:336-364`）。
3. `POST share/sharepage/save` body `{"fid_list":[...],"fid_token_list":[],"to_pdir_fid":"0","pwd_id":"<slug>","stoken":"...","pdir_fid":"0","pdir_save_all":true,"exclude_fids":[],"scene":"link"}` → `data.task_id` → 轮询；不可重试关键字 `permission denied/access denied/forbidden/unauthorized/file not found/share expired/share not found`（`:366-413`）。

`fid_token_list` 硬编码空数组；PLAN §8-#8 指出夸克通常要求 `fid` 与 `fid_token` 成对，**待确认**（`PLAN.md:947`）。`一键转存(链接,目标目录ID="0")`：解析→token→全部转存；UI 固定转存根目录（`:415-428`、`分享页.py:536-538`）。转存自己的分享 → 404 + 41017（`网络客户端.py:364-366`）。

`规范分享` 追加 `分享链接`（`share_url` 或生成）、`提取码`、`创建时间戳`、`是否有效`（`status==1`）（`:432-448`）；列表通常无 `passcode`，提取码常为空。

### 4.12 文件接口实测备注

- `file/sort` 有秒级延迟；刚 finish/删除后立刻查可能看不到（`PLAN.md:538`、`路径解析.py:55-56`）。
- `file/delete` 异步；HTTP 200 不等于删完，需轮询或二次列表确认（`PLAN.md:571-572`）。
- 删除是**真删**（进回收站），无二次确认 API；Rust UI 必须做「只删目标、同级存活」对照测试。
- `q`、`max_depth`、`recover` 三个字段名最易错（`PLAN.md:580-583`）。
- 总数只在 `metadata._total`；只读 `data.total` 常为 0/缺省。
- `file_type==0` 是目录（非常见「1=目录」）（`字段映射.py:96-97`）。

## 5. 上传

### 5.1 常量与分流

| 常量 | 值 | 证据 |
|---|---|---|
| 分片大小 | 4 MiB | `上传接口.py:41` |
| 单分片阈值 | 5 MiB；`<` 单次，`>=` 多片 | `:42`、`分片上传.py:78-80` |
| 默认桶 | `ul-zb` | `:43` |
| OSS URL | `https://{bucket}.pds.quark.cn/{obj_key}` | `:44` |
| OSS UA | `aliyun-sdk-js/1.0.0 Chrome Mobile 139.0.0.0 on Google Nexus 5 (Android 6.0)` | `:45-46` |
| 每片重试 | 3 次（额外；共 4），退避 `min(2^(n+1),10)` → 2/4/8s | `分片上传.py:50-51`、`:179-196` |
| 哈希块 | 1 MiB | `哈希计算器.py:79-96` |

`<5MiB`：`_单次上传`，1 次 OSS PUT（仍带 `partNumber=1&uploadId=...`），返回 `[(1,etag)]`，仍走合并+finish（`分片上传.py:83-120`）。`>=5MiB`：4MiB 切片，逐片串行 PUT；第 2 片起带增量 SHA1（`:123-172`）。恰好 5MiB → 4+1 两片（`规划分片`，`上传接口.py:87-96`）。注释明确不存在「完全不带 multipart 参数的简单 PUT」；`auth_meta` 必须带 `partNumber` 与 `uploadId`，否则 `Bad Parameter: [uploadId is null]`（`分片上传.py:10-24`）。

### 5.2 哈希

- `计算MD5和SHA1`：1MiB 块顺序读，同时更新 MD5/SHA1，返回 hex；进度 `(阶段,0..1)`（`哈希计算器.py:65-96`）。**不是** PLAN 早期写的 8KB，以代码为准。
- 提交 `md5`+`sha1`，**没有 crc64**（`上传接口.py:139-145`、`PLAN.md:511`）。
- 增量 SHA1 ctx = 该片**之前所有字节**的 SHA1 中间状态，base64(JSON)（`哈希计算器.py:9-31`、`:147-185`）：

```json
{"hash_type":"sha1","h0":"<uint32十进制>","h1":"...","h2":"...","h3":"...",
 "h4":"...","Nl":"<已处理位数>","Nh":"0","data":"","num":"0"}
```

`Nl=(片号-1)*片大小*8`；`Nh="0"`、`data=""`、`num="0"`；紧凑 JSON 后 base64（`:163-185`）。压缩是标准 SHA1 80 轮，初始状态 `67452301 EFCDAB89 98BADCFE 10325476 C3D2E1F0`（`:42-43`、`:101-144`）。**不需要 padding**：已处理字节=(片号-1)×4MiB，而 4MiB=65536×64，恒为完整块（`:26-30`、`PLAN.md:530`）。若改分片大小，必须保证 64 的倍数或实现真正 padding。离线验证 4/4 可还原 `hashlib.sha1()`（`PLAN.md:524`）。

性能警告：`计算增量SHA1上下文` 每次重新 `f.read((片号-1)*4MiB)` 并从初始状态压缩（`:163-174`），N 片总读取 O(N²)；纯 Python 压缩也慢。Rust 应维护滚动 SHA1 状态，只读一遍。

### 5.3 可复刻请求序列（第 1～N 步）

设文件 `F`、大小 `S`、目标 `pdir_fid`；MIME 由扩展名推断，缺省 `application/octet-stream`（`上传接口.py:49-51`）。

**第 0 步**：`md5, sha1 = MD5(F), SHA1(F)`（1MiB 块一次遍历）。

**第 1 步：预上传**

```
POST https://drive-pc.quark.cn/1/clouddrive/file/upload/pre
Cookie: <cookie>
Content-Type: application/json
（自动 pr=ucpro&fr=pc&uc_param_str=&__t=<ms>&__dt=1000）
```

body（`上传接口.py:107-127`）：

```json
{"ccp_hash_update":true,"parallel_upload":true,"pdir_fid":"0","dir_name":"",
 "size":12345678,"file_name":"a.bin","format_type":"application/octet-stream",
 "l_updated_at":1789322627000,"l_created_at":1789322627000}
```

时间戳当前毫秒。响应 `data`：`task_id`、`auth_info`、`upload_id`、`obj_key`、`bucket`、`callback`；无 `task_id` 抛错（`:128-135`）。

**第 2 步：提交哈希**

```
POST .../file/update/hash
{"task_id":"<task_id>","md5":"<hex>","sha1":"<hex>"}
```

响应未使用；`upload_id` 从预上传令牌取（`上传接口.py:139-145`）。注意 `分片上传.py:18-19` 注释说 `partNumber/uploadId` 由 `file/update/hash` 返回，与预上传 docstring/代码矛盾；以代码为准，标待确认。

**第 3 步：逐片授权 + OSS PUT**

每片 `n`（1-based，大小 `min(4MiB,剩余)`）。先算 `oss_date`（RFC1123 GMT，必须 locale 无关，见 5.4），构造 `auth_meta`：

```
PUT\n\n<mime>\n<oss_date>\n
x-oss-date:<oss_date>\n[x-oss-hash-ctx:<ctx>\n]x-oss-user-agent:<OSS_UA>\n
/<bucket>/<obj_key>?partNumber=<n>&uploadId=<upload_id>
```

代码（`上传接口.py:164-173`）：第二行空（Content-MD5 空），第三行 Content-Type，第四行 Date；`x-oss-*` 只列实际会发的行，顺序固定 date→hash-ctx→user-agent；第 1 片无 hash-ctx，签名串也不含该行。

授权请求：

```
POST .../file/upload/auth
{"task_id":"<task_id>","auth_info":"<auth_info>","auth_meta":"<上面字符串>"}
```

响应 `data.auth_key`；无则抛 `分片 n 未取到 auth_key`（`:175-182`）。随后裸 httpx PUT：

```
PUT https://{bucket}.pds.quark.cn/{obj_key}?partNumber=<n>&uploadId=<upload_id>
Content-Type: <mime>; x-oss-date: <oss_date>; x-oss-user-agent: <OSS_UA>; authorization: <auth_key>; X-Oss-Hash-Ctx: <ctx>（仅 n>=2）
```

- 不带 Cookie/Origin/Referer；OSS 用独立裸 Client（`网络客户端.py:481-503`）。body 是该片原始字节；Content-Length 自动。
- 只接受 HTTP 200；从响应头 `ETag` 取值并去两端双引号；无 ETag 抛错（`上传接口.py:199-208`）。
- 缺 ctx 时第 2 片 HTTP 400 `<Code>NoHashContext</Code>`/`<EC>0042-00000106</EC>`/`<PartNumber>2</PartNumber>`（`哈希计算器.py:11-19`、`PLAN.md:525-527`）。
- `auth_meta` 与实际头必须**逐字节一致**（三行 x-oss-*，顺序不能变），否则签名失败（`上传接口.py:18-23`）。

**第 4 步：合并**

CompleteMultipartUpload XML（`上传接口.py:76-84`）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<CompleteMultipartUpload><Part><PartNumber>1</PartNumber><ETag>"<etag1>"</ETag></Part>...</CompleteMultipartUpload>
```

每 Part 内有换行、Part 间有换行；注释「无换行」与代码不一致，以代码为准；ETag 在 XML 中带双引号。`xml_md5=base64(md5(xml.encode("utf-8")))`。

合并授权 `POST .../file/upload/auth`，`auth_meta`：

```
POST\n<xml_md5>\napplication/xml\n<oss_date>\n
[x-oss-callback:<base64(callback JSON)>\n]x-oss-date:<oss_date>\nx-oss-user-agent:<OSS_UA>\n
/<bucket>/<obj_key>?uploadId=<upload_id>
```

`callback` 来自预上传；存在时把 `json.dumps(callback,separators=(",",":"))` base64，作为 `x-oss-callback` 参与签名并实际发送（`:227-257`）。无 `auth_key` 抛 `合并授权未取到 auth_key`。

合并请求：

```
POST https://{bucket}.pds.quark.cn/{obj_key}?uploadId=<upload_id>
Content-Type: application/xml; x-oss-date: <oss_date>; x-oss-user-agent: <OSS_UA>; Content-MD5: <xml_md5>; authorization: <auth_key>; x-oss-callback: <callback_b64>（若有）
```

**200 或 203 都算成功**；203 表示合并成功但 callback 失败，只 warning（`:265-273`、`PLAN.md:514`）。其他状态抛 `OSS 合并失败：HTTP ...`。

**第 5 步：finish**

```
POST .../file/upload/finish
{"task_id":"<task_id>","obj_key":"<obj_key>"}
```

响应 `data` 含 `fid/finish/md5/sha1`；取 `fid`（`:277-283`、`上传总调度.py:146-155`）。

### 5.4 `_OSS日期()` 的 locale 坑

`上传接口.py:54-73` 用 `email.utils.formatdate(usegmt=True)` 生成 RFC1123 GMT，如 `Sun, 13 Sep 2026 17:54:18 GMT`。**绝不能**用 `datetime.strftime("%a, %d %b %Y %H:%M:%S GMT")`：Qt `QApplication` 会 `setlocale(LC_ALL,"")`，把 `LC_TIME` 从 `C` 改成 `zh_CN.UTF-8`，`%a/%b` 变中文，得到 `日, 13 9月 2026 ...`，OSS 拒绝 `The input parameter date is not valid. date should be GMT format`（`:57-71`）。纯 CLI 测试发现不了（CPython 启动只设 `LC_CTYPE`，不动 `LC_TIME`），只有起 QApplication 复现（`:67-68`）。Rust 应用固定英文星期/月份表或 `httpdate`/`time`，不要依赖 locale。

### 5.5 串行、重试、进度

- 分片**串行**，不并发：增量哈希依赖前序全部字节；实测 10MB 3 片约 2 秒，带宽远未打满（`分片上传.py:33-36`）。
- `_传一片` 对「取授权+OSS PUT」捕获**所有异常**重试 3 次，退避 2/4/8s（上限 10）；含签名/4xx 也会重试（`:175-197`）。
- 进度：哈希 0~0.10、预上传 0.10、提交哈希 0.12、分片 0.15~0.90、合并 0.90、finish 0.97、完成 1.0（`上传总调度.py:104-147`）；速度日志 MB/s（`:115-119`）。

### 5.6 秒传

无独立接口；`file/upload/pre` 本身查重（`秒传服务.py:5-14`）。防御式判定（`:44-63`）：有 `fid` 且（`finish is True` 或无 `upload_id`）才算命中；命中跳过后续直接返回 `fid`。有 `fid` 但有 `upload_id` 不算，继续正常上传。夸克秒传字段**未实测确认**（`:16-18`、`PLAN.md:857`）；Rust 保留「不命中就走正常上传」的保守策略。

### 5.7 上传结果/记录

`上传结果` dataclass 只在内存（`上传总调度.py:35-61`）：

```json
{"fileName":"a.bin","fileId":"<fid>","fid":"<fid>","fileSize":123,"size":123,
 "md5":"...","sha1":"...","taskId":"...","分片数":3,"秒传":false}
```

`fileId` 是兼容旧 GUI 的别名，`fid` 是新字段。没有持久化上传记录/数据库；「上传记录」页已删（`PLAN.md:837`）。

### 5.8 失败/垃圾文件

预上传+提交哈希后服务端已建上传记录；后续分片/合并失败可能留下**幽灵文件**（`PLAN.md:539`）。代码没有取消/清理上传接口。Rust 应在失败时提示，产品层考虑重传覆盖/删除残留。

## 6. 下载

### 6.1 直链

```
POST https://drive-pc.quark.cn/1/clouddrive/file/download
{"fids":["<fid>","..."]}
```

响应 `data` 为 list（或 `data.list`）；每项 `fid/file_name/size/download_url`（`文件接口.py:283-295`）。单文件优先精确匹配 `fid` 且直链非空，否则第一条有直链，否则抛 `接口错误`（`:297-312`）。下载前确保有 `__puus`，没有则 `GET member` 补（`下载服务.py:93-98`）。

### 6.2 请求头与传输

`下载服务._下载请求头()`（`下载服务.py:107-117`）：

```
user-agent: Mozilla/5.0 (Windows NT 10.0; WOW64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/94.0.4606.71 Safari/537.36 Core/1.94.225.400 QQBrowser/12.2.5544.400; referer: https://pan.quark.cn/; accept: */*; cookie: <完整 Cookie 字符串>
```

- UA 常量 `:35-37`，与 API 默认 UA 相同；Referer/Cookie 是防盗链回调会读的，缺 Cookie/`__puus` 会 403（`:8-16`）。
- 独立 `httpx.Client(timeout=...,http2=False,follow_redirects=True,headers=下载头)`（`:165-170`）；**必须 follow_redirects**，直链可能 302 到 CDN（`:19`）。
- `client.stream("GET",直链)`；只接受 HTTP 200；206 视为失败（`:171-174`）。64KiB 块写盘；进度 `(已下载,总大小)`；`Content-Length` 存在时覆盖 metadata 的 `size`（`:34`、`:175-187`）。
- **没有** Range/Content-Range/断点续传/并发分片；全项目无 Range 实现。也没有 Content-Disposition 解析，文件名用 API `file_name` 或调用方传入。

### 6.3 落盘/去重/清理

- 目标目录 `mkdir(parents=True,exist_ok=True)`。
- `覆盖=False`：`去重路径` 生成 `名字 (1).ext`…，最多 9999 次（`:43-59`）。按 `Path.stem/suffix` 拆分，`a.tar.gz` → `a.tar (1).gz`（小瑕疵）。
- `覆盖=True`：直接用目标名；UI 下载选中文件传 `覆盖=True`，用户已在保存对话框确认（`文件浏览页.py:476-479`）。
- 先写 `<目标>.part`，成功后 `replace(目标)`；失败删 `.part`，并删 0 字节目标（`:132-144`、`:224-241`）。返回 `{"path","size","file_name","fid"}`（`:243-248`）。

### 6.4 重试与 `__puus` 自愈

1. 请求前：`_确保下载凭证()`，Cookie 无 `__puus=` 就 `GET member` 补一次（`:93-98`）。
2. 请求后：异常文本含 `RequestDeniedByCallback`/`auth miss`/`auth not found` 视为 CDN 回调拒绝；删半成品，`_刷新下载凭证(强制=True)`，**重试 1 次**（最多 2 次尝试）；仍失败抛 `接口错误`（`:226-239`）。
3. 刷新依赖 `网络客户端._捕获刷新Cookie` 合并响应 `Set-Cookie: __puus`（`网络客户端.py:242-261`）；**不写回凭证仓库**，重启仍用旧 Cookie。Rust 应持久化新值。

错误文案（`:119-130`）：

- `RequestDeniedByCallback`+`auth miss` → 「下载被 CDN 拒绝（403 RequestDeniedByCallback / auth miss）：Cookie 缺少或已失效的 __puus。原始响应：...」
- 其他回调拒绝 → 「下载被 CDN 防盗链拒绝（403）：...」
- 其他 → 「下载失败：HTTP <code> <text 前300字>」

### 6.5 批量/内存

- `下载多个` 串行；每项先取直链拿文件名/大小，再调 `下载到文件`（后者又取一次直链）→ 每文件 **2 次** `file/download`；无并发（`:250-272`）。Rust 可合并为一次取直链再逐个下载。
- `下载到内存`：`httpx.Client(timeout=120,follow_redirects=True)` GET，只接受 200；同样回调拒绝刷新重试 1 次（`:274-295`）。
- 没有 MD5/SHA1 校验，也没有 Content-Length 完整性校验；只按字节进度。Rust 建议加可选校验。

```
（自动 pr=ucpro&fr=pc&uc_param_str=&__t=<ms>&__dt=1000）
```

实测字段（注释，2026-09-14）：`total_capacity`/`use_capacity`/`secret_total_capacity`、`member_type`（如 `SUPER_VIP`）、`exp_at`/`subscribe_status`、`deep_recycle_stat`（回收站保留策略）；可能还有 `member_info`、`member_status`、`subscribe_pay_channel`、`extend_capacity_composition`（`取会员权益` 合并这些子对象，`:93-113`）。`取容量` 派生（`:73-91`）：

```json
{"total_capacity":总,"use_capacity":已用,
 "free_capacity":max(0,int(总)-int(已用)),"member_type":会员类型}
```

总量/已用可能是字符串或数字；`int()` 失败则 free=0。**没有** `/capacity`、`/file/capacity`、`/member/capacity`（均 404）；`/v1/user/me` 也不存在（`认证服务.py:5-21`、`PLAN.md:536`）。昵称/头像：扫码登录把 `account/info` JSON 存进登录结果 `用户信息`（`登录服务.py:264-268`、`:294-299`），没有单独「取当前用户」接口；字段待确认。

`取会员权益` 抽取 `member_type/subscribe_status/exp_at/subscribe_pay_channel`，再 `update(member_info)`、`update(member_status)`，以及 `deep_recycle_stat`、`extend_capacity_composition`（后 update 覆盖前值）。`是否已登录`：本地 `凭证仓库.是否有效(安全余量=60.0)`；无可复用客户端则只信本地，否则再 `GET member` 探测（`:115-127`）。当前 UI 启动只做本地检查（`主界面.py:164-176`）。

### 7.2 任务

`GET https://drive-pc.quark.cn/1/clouddrive/task?task_id=<id>&retry_index=<n>`（`任务接口.py:53-64`）；`retry_index` 每次递增，从 0 开始（`:85-86`）。`data.status`：

| status | 含义 | 行为 |
|---|---|---|
| 0 | 排队 | 继续 |
| 1 | 进行中 | 继续 |
| 2 | 完成 | 返回 `data`（可能含 `share_id`） |
| 3 | 失败 | 抛 `任务错误("<描述>失败：<message 或摘要>")` |

`message` 失败原因；`tq_gap` 服务端建议间隔（毫秒），存在时 `max(0.2,min(5.0,tq_gap/1000))`，否则 1.0s（`:108-116`）。默认最长 60s；超时抛 `任务错误("<描述>超时（60 秒，轮询 N 次，task_id=...）")`（`:118-119`）。不可重试关键字命中立即抛；`"capacity limit"`（小写）或「容量不足」也立即抛（`:102-106`）。删除/重命名/移动/创建分享/转存都复用。状态按 int 比较；若服务端返回字符串 `"2"` 会轮询到超时（待确认）。

### 7.3 其他

回收站 API 有（§4.6），GUI 入口已删（`PLAN.md:837`）。上传记录无 API/无页面/无持久化。离线下载/云添加/磁力未实现；`表单文件请求` 可作 `resolve_torrent` 雏形但接口层没调用（`网络客户端.py:403-466`）。短信、埋点/遥测均无。

### 8.4 会话过期与自愈

| 情况 | 行为 | Rust 建议 |
|---|---|---|
| 本地 `expires_at` 到期 | `取Cookie` 返回 `""`，UI 提示重登 | 登录态检查 + 明确错误码 |
| 服务端 401/403 | 抛「登录已过期或 Cookie 无效，请重新登录」；**不自动重登** | 捕获后跳登录，不无限重试 |
| 缺 `__puus` | 下载前 `GET member` 补；仍缺警告 | 登录后立即补并持久化 |
| `__puus` 滚动失效 | 403 回调拒绝时强制刷新并重试 1 次 | 同样，但保存新值 |
| `__puus` 刷新成功 | 只更新内存 `网络客户端.Cookie`，**不写凭证仓库** | 写回凭证文件（0600） |
| 上传/其他 401 | 不重试、不刷新 | 统一会话中间件 |
| 无 refresh token | 只能重新扫码/手填 | 明确 UI 文案 |

风控观察：无设备指纹、无签名（除 OSS）、无 `x-requested-with`、UA 固定、Origin/Referer 固定、Cookie 明文落盘。服务端可能按 Cookie/UA/IP 风控；代码无限速、验证码、代理轮换。Rust 不要高并发，上传保持串行更接近已验证形态。

### 9.2 ⚠️ 实测结论（逐条）

1. 删除**绝不能**传 `current_dir_fid`；`fid_list+current_dir_fid="0"` 会清空根目录（`文件接口.py:174-185`、`PLAN.md:552-572`）。
2. 删除正确字段是 `action_type/filelist/exclude_fids`（同上）。
3. `file/search` 用 `q` 不是 `keyword`，错用会静默返回无关结果（`文件接口.py:103-104`）。
4. `file/tree` 用 `max_depth` 不是 `_depth`（`PLAN.md:581`）。
5. 回收站恢复用 `recover` 不是 `restore`，必须 `select_mode`（`文件接口.py:228-229`）。
6. 分享列表不返回 `passcode`，必须逐条 `share/password`（`字段映射.py:242`、`分享页.py:377-379`）。
7. 取消分享必须 `share_ids` 数组；`share_id` 标量静默 no-op；`share_id` 数组 500（`分享接口.py:215-223`）。
8. 两套分享 ID 不相等：32 位 hex 管理、URL slug 转存（`分享接口.py:22-29`）。
9. 下载缺 `__puus` 会 403 `RequestDeniedByCallback/auth miss`；扫码不直接下发，需 `member` 补（`登录服务.py:270-286`、`下载服务.py:8-16`）。
10. `ctoken` 只活约 10 分钟，不能参与整份凭证过期 min（`登录服务.py:307-310`）。
11. 凭证权限必须 0600；普通 open 会退化 644（`凭证仓库.py:192-196`）。
12. `_OSS日期` 不能用 locale 相关 `strftime`；Qt 会把 `LC_TIME` 改中文（`上传接口.py:54-73`）。
13. 缺 `X-Oss-Hash-Ctx` 时第 2 片 400 `NoHashContext`/EC `0042-00000106`（`哈希计算器.py:11-19`）。
14. `auth_meta` 与实际头逐字节一致，x-oss-* 顺序固定（`上传接口.py:18-23`）。
15. 合并 203 也算成功（callback 失败），不能只认 200（`上传接口.py:265-273`）。
16. `GET config` 的 `allow_ccp_hash_update:false` 是红鲱鱼，不要省略上下文（`PLAN.md:531`）。
17. `file/sort` 秒级延迟；刚操作后可能瞬时空页，空结果要重试（`路径解析.py:55-64`、`PLAN.md:588`）。
18. 预上传+提交哈希后失败会留幽灵文件（`PLAN.md:539`）。
19. 单文件分享 title 被服务端忽略，统一用文件名（`分享对话框.py:59-65`）。
20. 转存自己的分享返回 404+41017（`网络客户端.py:364-366`）。
21. `file_type==0` 是目录（`字段映射.py:96-97`、`文件接口.py:39-40`）。
22. `created_at/updated_at/expired_at` 是毫秒（`字段映射.py:52-58`、`分享页.py:260-261`）。
23. 总数只在 `metadata._total`（`文件接口.py:17-26`）。
24. HTTP 404/400 也可能带业务 JSON，先解析再 raise（`网络客户端.py:363-388`）。
25. 扫码 HTTP 非 200/异常被当等待，会轮询到 300s 超时（`登录服务.py:161-173`、`:203-218`）。

### 10.3 注意事项（按严重度）

1. **删除安全**：只发 `action_type=2,filelist,exclude_fids`，绝不带 `current_dir_fid`；集成测试「建 A/B→删 A→验 B 存活、根目录未清空」（`PLAN.md:571-572`）。
2. **取消分享字段**：`share_ids` 数组；删后回查，否则静默 no-op 当成功（`分享接口.py:215-262`）。
3. **两套分享 ID**：管理用 32 位 `share_id`，转存用 URL slug；解析返回 slug，不能拿去 `share/delete`。
4. **`__puus` 生命周期**：扫码后 `member` 补；每次响应检查 `Set-Cookie`；下载 403 强制刷新重试一次；刷新后持久化（Python 没做）。
5. **HTTP 404/400 + JSON**：先解析 body 再判 HTTP；保留 `code/message/req_id`；不要只 `error_for_status()`。
6. **成功判定**：`status==200 && (code==0 || code 缺失)`；不要只信 code。
7. **分片哈希**：4MiB；第 2 片起 ctx 强制；`auth_meta` 与实际头逐字节一致；顺序 date→hash-ctx→user-agent；合并接受 200/203。
8. **OSS 日期**：固定英文 RFC1123 GMT，禁用 locale 相关格式化。
9. **合并 XML**：ETag 带引号；`Content-MD5` 基于最终 XML；callback JSON 紧凑后 base64；签名串与实际请求一致。
10. **分片性能**：Python 重读前缀 + 纯 Python SHA1，O(N²)；Rust 维护滚动状态，只读一遍。
11. **`file/sort` 延迟**：写后可能瞬时空页；空结果重试 1 次（1.5s）或轮询；写后清路径缓存。
12. **`metadata._total`**：总数不在 `data.total`；`_page` 从 1 开始。
13. **`file_type==0` 是目录**，`dir is True` 也是目录；不要按常见约定写。
14. **毫秒时间戳**：`created_at/updated_at/expired_at/l_created_at/l_updated_at` 都是毫秒；>1e12 除 1000。
15. **中文 URL/header**：路径含中文百分号编码；header 必须 ASCII；Cookie 值里的 `%2F` 原样保留，不二次解码。
16. **下载**：必须 Cookie+Referer+QQBrowser UA；`follow_redirects=true`；只接受 200；无 Range，断点续传需自研（服务端是否支持待确认）。
17. **文件名去重**：`名字 (n).ext`；`.tar.gz` 的 stem/suffix 要自定义，避免 `a.tar (1).gz`。
18. **凭证安全**：0600；不写日志；不放 URL；Rust 可用 secrecy/zeroize；可选 keyring；仓库无 domain/path，重放拼 Cookie 头，注意子域差异。
19. **路径缓存**：无 TTL；写后清；同名取第一个；`..` 语义按需修正；没有 fid→完整路径 反查，GUI 自己维护路径栈。
20. **任务轮询**：`retry_index` 递增；失败状态 3 立即抛；`tq_gap` 夹取 0.2~5s；容量不足等立即失败。
21. **手动 Cookie 校验**：改用 `GET member`，不要用 `GET capacity`。
22. **二维码**：本地生成，内容是 `su.quark.cn/4_eMHBJ?...`；无用户码；约 5 分钟；轮询 2s/300s。
23. **上传失败残留**：预上传+哈希后失败会留幽灵文件；UI 提示并考虑清理/重传。
24. **限速/风控**：无设备指纹；固定 UA/Origin/Referer；不要高并发；上传串行；下载并发需自测。
25. **代理**：Python 未显式配置，httpx 可能读环境代理；Rust reqwest 默认也读，按产品需求显式设置/禁用。

### 10.4 最小验收

1. 扫码登录 → 凭证 0600、含 `__kps/__uid/__puus` → 重启仍能列根目录；手动 Cookie（含 `__puus`）→ 校验走 `member` → 列目录成功。
2. 列根目录：`metadata._total` 正确、中文名正常、`file_type==0` 判目录；新建目录 → 上传 1KB 与 6MB（2 片，第 2 片带 ctx）→ 列表可见 → 下载字节一致。
3. 缺 `__puus` 凭证 → 观察 `member` 补全/403 重试且文件完整；建 A/B → 删 A → 确认 B 仍在、根目录未清空。
4. 创建分享（公开/随机/自定义）→ 详情拿 `share_url/passcode` → 列表 → 取消 → 回查确认真的没了；解析 `https://pan.quark.cn/s/<slug> 密码：1234` → token → detail → save → task 完成。
5. 转存自己的分享 → 404/41017 且 UI 可读；分享列表不带 `passcode` 时按需 `share/password`。
6. 任务失败/超时/容量不足提示；退出登录删凭证，重新登录可用。

**一句话总结**：Cookie 认证 + `file/*` 云盘 API + OSS 4MB 分片直传 + 流式下载；协议核心已验证，但手动 Cookie 校验走 `capacity`、`fid_token_list` 空数组、下载无 Range/校验、`__puus` 不持久化等缺口，Rust 重写按第 10 节逐项规避。
