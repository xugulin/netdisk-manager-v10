### 2.2 API 客户端默认请求头（原文）

每请求再注入（`网络客户端.py:207-224`）：
```http
content-type: application/json          # 可置 None（multipart 时不注入）
did: <32 位 hex>
dt: 4
smid: <Base64 设备指纹>
traceparent: 00-<32hex>-<16hex>-01
authorization: Bearer <access_token>    # 有令牌时
```

- 未显式配置代理/证书校验；httpx `trust_env` 默认 True，因此会读取 `HTTP(S)_PROXY`/`NO_PROXY` 环境变量（🔶 库默认行为）。

### 2.4 设备身份生成规则（可复刻）
`设备身份.py`：
- `设备ID` = `uuid.uuid4().hex`，32 位小写十六进制；首次生成后写入 `~/.光鸭云盘/设备信息.json` 的 `"设备ID"`（`设备身份.py:35-41`）。
- `设备指纹`（smid）：若已存在直接用；否则取：
```python
原始字段 = [
    platform.system(),          # 如 "Linux"/"Darwin"/"Windows"
    platform.release(),         # 内核版本
    platform.machine(),         # 如 "x86_64"
    platform.python_version(),  # 如 "3.12.x"
    str(uuid.getnode()),        # 网卡 MAC 转 48 位整数（无 MAC 时可能随机）
]
指纹 = base64.b64encode("|".join(原始字段).encode("utf-8")).decode("utf-8")
```
（`设备身份.py:50-61`）
- `dt` 固定 `"4"`（`设备身份.py:64-66`）。
- 设备 ID/指纹持久化，跨进程稳定；但**跨平台/换 Python 版本/换网卡会变**，服务端可能视为新设备。
- Rust 移植：`did=Uuid::new_v4().simple().to_string()`；`smid` 不应照抄 Python 平台字段（Rust 没有 python_version）。建议继续持久化原 smid（若要与旧会话兼容），或改用稳定的 `os|os_version|arch|app_version|machine_id` 五元组，但需实测服务端是否校验内容——**待确认**。`uuid.getnode()` 在 Rust 可用 `mac_address`/`machine-uid` crate 替代。
### 2.5 追踪上下文（traceparent）
`追踪上下文.py`：
```python
def 生成追踪ID(): return secrets.token_hex(16)   # 32 hex
def 生成跨度ID(): return secrets.token_hex(8)    # 16 hex
def 生成追踪头(追踪ID=None):
    return f"00-{追踪ID or 生成追踪ID()}-{生成跨度ID()}-01"
```
（`追踪上下文.py:13-30`）
- 每个请求生成一个新的 traceparent；没有跨请求 trace id 传播。
- 正则校验：`^00-([0-9a-f]{32})-([0-9a-f]{16})-[0-9a-f]{2}$`（`追踪上下文.py:33`）。
- Rust：`format!("00-{}-{}-01", hex32, hex16)`；可用 `rand` 生成，无需 W3C crate。服务端只透传/记录，未见校验逻辑（❓是否必需）。
### 2.6 埋点签名（完整可复刻）
签名实现（`核心/接口/埋点签名.py:8-12` 原文）：
```python
def 计算埋点签名(data_list: str, 时间戳: int, appid: int, 密钥: str) -> str:
    """推测算法：sha1(data_list + t + appid + 密钥)"""
    待签名 = f"{data_list}{时间戳}{appid}{密钥}"
    return hashlib.sha1(待签名.encode("utf-8")).hexdigest()
```
上报（`埋点上报.py:46-90`）：
1. 事件列表 JSON：`json.dumps(events, ensure_ascii=False).encode("utf-8")`。
2. `gzip.compress(...)`。
3. `base64.b64encode(...).decode("utf-8")` → `data_list`（`H4sI...` 开头）。
4. `t = int(time.time() * 1000)`（毫秒）。
5. `sign = sha1(data_list + t + appid + 密钥)` 的 **小写 hex**；字符串直接拼接，**无分隔符**。
6. POST `https://analysis-rcv.guangyapan.com/sync_data`，`Content-Type: application/x-www-form-urlencoded`，表单：
```text
data_list=<base64(gzip(json))>&gzip=1&appid=1&t=<ms>&sign=<sha1hex>
```
7. 额外头：`referer: https://www.guangyapan.com/`，UA 为 Chrome 151/Linux（`埋点上报.py:77-85`），超时 15s。
⚠️ **密钥为空**：`默认密钥 = ""`（`埋点上报.py:35`），注释直言“需逆向获取；为空时上报通常被服务端忽略”。所以当前埋点签名可算出但大概率无效。
⚠️ `gzip.compress` 会写入当前时间（mtime）到 gzip 头，但签名针对压缩后的 base64，故重放时 gzip 头必须是同一份字节；Rust 侧若重算需保留原始 `data_list`，不要只重算签名。
⚠️ `appid=1`、`gzip=1` 固定；`appid` 为字符串写入表单，签名字符串里用整数（Python f-string 结果相同）。
⚠️ 埋点模块未被 GUI 引用（grep 仅自身），属于可选能力；Rust 首版可不实现。

### 2.8 URL 编码与请求头校验
- `_安全URL`：仅当整条 URL 非 ASCII 时，对 path/query/fragment 百分号编码；safe 集合：path `"/%:@&=+$,;~()*!'"`，query `"=&%:@+,;~()*!'"`（`网络客户端.py:64-83`）。ASCII URL 原样返回（含空格等非法字符不会修）。
- `_校验请求头`：丢弃 `None`；把所有 value 转 str；含非 ASCII 立即抛 `ValueError`（`网络客户端.py:86-102`）。这是为了避开 RFC 7230 与 Python locale 问题（如中文月份）。
- Rust：用 `url::Url` 解析并 `percent-encoding`，不要手拼；header 值用 `HeaderValue::from_str` 校验。
### 2.9 统一错误模型（`接口错误`）
```python
class 接口错误(Exception):
    def __init__(self, 消息, 状态码=None, 业务码=None, 请求ID=None)
```
（`网络客户端.py:152-163`）
触发点：
1. HTTP 401 且 `需要认证=True` → `接口错误("未登录或登录已过期", 状态码=401, 请求ID=x-request-id)`（`网络客户端.py:275-277`）。
2. `响应.raise_for_status()`：其它 4xx/5xx 抛 **httpx.HTTPStatusError**（不是接口错误）。
3. 响应非 JSON → `接口错误("响应不是合法 JSON: ...")`（`网络客户端.py:281-287`）。
4. 顶层 `code` 不在白名单 → `接口错误(msg, 状态码, 业务码, x-request-id)`（`网络客户端.py:226-239`）。
- 默认允许业务码：`(None, 0, 147, 156, 200)`（`网络客户端.py:34-39`）。
- 调用方可通过 `允许业务码=(159,)` 扩展（`云添加接口.py:130-140`）。
- 请求 ID 从响应头 `x-request-id` 取；Rust 侧应保留到错误类型。
- OSS 路径不经过统一错误模型：`上传接口.OSS直传*` 自行检查 `status_code >= 400` 后 `raise_for_status()`（`上传接口.py:376-385, 437-445`）。

### 3.3 令牌刷新
```http
POST https://account.guangyapan.com/v1/auth/token
Content-Type: application/json
<刷新专用账户头，x-sdk-version=9.0.2>

{"grant_type":"refresh_token",
 "refresh_token":"gy....",
 "client_id":"aMe-8VSlkrbQXpUR"}
```
（`令牌仓库.py:65-130`）
- 只接受 HTTP 200 + JSON 含 `access_token`；否则返回 None（不抛）。
- 新令牌字段：`access_token`、`expires_in`（默认 7200）、`refresh_token`（若空保留旧值）、`sub`（若空保留旧值）（`令牌仓库.py:272-282`）。
- 提前量 `提前刷新余量 = 300` 秒：`now >= 过期时间戳 - 300` 即刷新（`令牌仓库.py:36-37, 227-234`）。
- 双检锁 + 单飞：`_刷新锁` 内二次检查，其他线程等锁后复用结果（`令牌仓库.py:236-284`）。
- `获取访问令牌(安全余量=0)`：需要刷新则先刷新；若仍为空或已过期返回 None（`令牌仓库.py:288-304`）。
- **注意**：刷新只在“取令牌”时按时间触发；`网络客户端` 收到 401 **不会**自动刷新/重放请求（`网络客户端.py:275-277`）。Rust 侧建议加 401→refresh→单次重试，但要防循环；Python 行为不是这样。
### 3.4 获取当前用户
```http
GET https://account.guangyapan.com/v1/user/me
Content-Type: application/json
authorization: Bearer <access_token>
```
（`认证服务.py:18-31`）
- 账号域名，`带业务头=False`（无 did/dt/smid/traceparent）。
- 响应若含顶层 `data` 则返回 `data`，否则原样返回。
- 无 token 时 `RuntimeError("无有效访问令牌")`。
### 3.5 凭证保存/读取/失效/登出
- 保存：`保存令牌(token, expires_in, refresh_token?, sub?)` → 写内存 + **立即写盘**（`令牌仓库.py:200-223`）；没有文件锁/原子替换，多进程可能互相覆盖。
- 读取：构造单例 `全局令牌仓库` 时 `_加载()`（`令牌仓库.py:152, 166-182`）；即使已过期也先载入内存，取用时再判断/刷新。
- 失效：`获取访问令牌()` 返回 None（刷新失败且过期）；没有“删除刷新令牌”的单独 API。
- 登出：`清空令牌()` 清内存并 **删除** 令牌文件（`令牌仓库.py:326-338`）；UI 同时断开网络客户端（`主界面.py:369-397`）。没有服务端 logout/revoke 请求。
- 密码登录：**不存在**（grep `password` 仅字段映射）。
- ⚠️ 实测/源码备注：
  - access_token 有效期实际由服务端 `expires_in` 决定，代码按本地时钟累加；时钟偏差会导致提前/延后刷新。
  - 刷新响应若轮换 refresh_token 会更新；若服务端不返回则沿用旧值。
  - 刷新失败后 UI 不会自动弹登录，只在下次请求报 401/接口错误。
  - 扫码轮询的 `interval` 由服务端给，代码默认 3s；没有 `slow_down` 处理。
  - 短信登录的 `x-captcha-token` 只用于发短信，校验/登录步骤不带。

### 5.3 第 2 步：OSS V1 签名（单 PUT，完整可复刻）
请求（`上传接口.py:355-389`）：
```http

Content-Length: <字节数>
Content-Type: <按扩展名推断，兜底 application/octet-stream>
x-oss-date: <RFC1123 GMT>
x-oss-security-token: <creds.sessionToken>
x-oss-user-agent: aliyun-sdk-js/6.23.0 Chrome 151.0.0.0 on Linux 64-bit
Authorization: OSS <creds.accessKeyID>:<base64(HMAC-SHA1(secretAccessKey, StringToSign))>
```
此外还显式发送浏览器仿真头（`上传接口.py:329-348`）：`Accept: */*`、`Accept-Language: zh-CN,zh;q=0.8`、`Origin`、`Referer`、`Sec-Fetch-Dest/Mode/Site`、`Sec-GPC: 1`、`sec-ch-ua: "Not=A?Brand";v="99", "Brave";v="151", "Chromium";v="151"`、`sec-ch-ua-mobile: ?0`、`sec-ch-ua-platform: "Linux"`、`User-Agent: <BROWSER_UA>`。这些**不参与** OSS 签名（只有 `x-oss-*` 参与）。
签名原文（`上传接口.py:126-190`，逐行可复刻）：
```python
def _计算OSS签名(method, content_md5, content_type, date, oss_headers,
                 bucket, object_path, access_key_id, access_key_secret):
    # 1. CanonicalizedOSSHeaders
    排序后 = sorted(
        (str(k).lower(), str(v).strip())
        for k, v in oss_headers.items()
        if str(k).lower().startswith("x-oss-")
    )
    canonical_oss_headers = "".join(f"{k}:{v}\n" for k, v in 排序后)

    # 2. CanonicalizedResource
    canonical_resource = f"/{bucket}/{object_path.lstrip('/')}"

    # 3. StringToSign
    string_to_sign = (
        f"{method}\n"
        f"{content_md5}\n"
        f"{content_type}\n"
        f"{date}\n"
        f"{canonical_oss_headers}"
        f"{canonical_resource}"
    )

    # 4. HMAC-SHA1
    h = hmac.new(access_key_secret.encode("utf-8"),
                 string_to_sign.encode("utf-8"), sha1)
    signature = base64.b64encode(h.digest()).decode("ascii")
    return f"OSS {access_key_id}:{signature}"
```
调用参数（`上传接口.py:316-326`）：
```python
content_md5 = ""                       # ★ 不发送 Content-MD5，StringToSign 中为空串
content_type = final_content_type
date = oss_headers["x-oss-date"]       # ★ Date 位置填 x-oss-date 的值
oss_headers = {"x-oss-date", "x-oss-security-token", "x-oss-user-agent"}
bucket = 令牌["bucketName"]
object_path = 令牌["objectPath"]
```
要点（⚠️ 每条都是坑）：
1. **不发送 `Date` 头**，只用 `x-oss-date`；StringToSign 的 Date 行填 `x-oss-date` 的值。OSS 允许，但要求两端一致。
2. `x-oss-date` 必须是 **RFC1123 GMT 英文**：`format_datetime(datetime.now(timezone.utc), usegmt=True)`（`上传接口.py:96-103`）；不要用本地 `strftime("%a/%b")`（中文 locale 会出中文）。
3. `CanonicalizedOSSHeaders` 含 `x-oss-date` 自己，按小写键字典序，`k:v\n`，value 去首尾空格；末尾**必须**有 `\n`（拼接时每个头都带）。
4. `CanonicalizedResource` 以 `/` 开头，`/{bucket}/{objectPath}`；objectPath 去前导 `/`。若 objectPath 含特殊字符，请求 URL 做百分号编码，但签名资源按 OSS 规范用解码后的路径（Python 直接拼 raw objectPath；Rust 需注意，❓特殊字符场景待实测）。
5. `Content-MD5` 行空串；不要额外计算 MD5 放进头，否则签名要包含它。
6. 签名只覆盖 `method/content-md5/content-type/date/canonical-oss-headers/canonical-resource`；`Content-Length`、浏览器头、`Authorization` 本身不参与。
7. `x-oss-security-token` 必须同时出现在签名头和实际请求头；缺一不可。
8. `x-oss-user-agent` 参与签名（因为以 `x-oss-` 开头）。Rust 侧可以**完全不发**这个头，减少签名变量；服务端不要求。
9. Host 由 `fullEndPoint` 决定；不要自己拼 `bucket.endpoint` 与 `fullEndPoint` 混用（若 `fullEndPoint` 是 CDN/CNAME，签名 bucket 仍用 `bucketName`）。
10. ETag 响应头通常带双引号；下一步 `gcid = etag.strip('"')`（`上传接口.py:565`）。

#### 5.7.1 oss2 调用方式

#### 5.7.3 V1 签名在 multipart 下的 StringToSign
```text
StringToSign =
  HTTP-Verb + "\n" +
  Content-MD5 + "\n" +          # 空串（不发）
  Content-Type + "\n" +         # Initiate 无 body 时可为空；UploadPart=application/octet-stream；Complete=application/xml
  Date + "\n" +                 # oss2 用 Date；项目手工实现用 x-oss-date 填这里
  CanonicalizedOSSHeaders +     # 所有 x-oss-*（含 x-oss-security-token），小写键排序，k:v\n
  CanonicalizedResource         # /bucket/object + "?子资源排序"
```
- 签名算法：`base64(HMAC-SHA1(secretAccessKey, StringToSign))`，头 `Authorization: OSS <AccessKeyId>:<signature>`。
- 版本选择：**V1**。项目手工签名器明确是 V1；oss2 `Bucket(StsAuth, ...)` 默认也是 V1（未指定 V4）。不要为了“新”切 V4——STS + V4 的 canonical request 完全不同（`x-oss-content-sha256`、credential scope 等），会直接 403。
- 是否需要 `x-oss-date`：两种都行。V1 下发送 `Date`（oss2 默认）或 `x-oss-date`（项目手工）均可，但 StringToSign 的 Date 行必须与所发头一致；若同时发两个，行为易错，**只选一个**。
- `x-oss-user-agent`：可选。项目手工路径发送并签名；oss2 可能发 `User-Agent`/`x-oss-user-agent`（❓具体值随 SDK 版本）。Rust 建议：**不发** `x-oss-user-agent`，只发 `x-oss-security-token`，签名变量最少。
- `Content-MD5`：项目**不发**；StringToSign 留空。Rust 可保持空以降低复杂度；若加，必须 base64(MD5(body)) 且参与签名。
- 回调：项目**没有** `x-oss-callback`/`callback-var`；`callbackVar` 字段被忽略。不要实现回调，靠 `get_info_by_task_id` 确认。

- `urlDuration` 单位/含义源码未用（❓ 秒？）；`speedupSignature` **完全未使用**（grep 仅注释/字段映射）；`requestId` 未用。

### 6.2 下载请求
GUI 实现（`文件浏览页.py:477-523`）：
```python
下载信息 = 文件接口.取下载地址(fileId)
signedURL = 下载信息["signedURL"]
with httpx.Client(timeout=Timeout(connect=30, read=3600, write=3600, pool=30),
                  http2=False, follow_redirects=True) as 客户端:
    with 客户端.stream("GET", signedURL) as 响应:
        响应.raise_for_status()
        for 数据块 in 响应.iter_bytes(chunk_size=64*1024):
            写文件
```
- **不带** `authorization`/`did`/`dt`/`smid`/`traceparent`；使用 httpx 默认 UA（`python-httpx/x.y`）。
- `follow_redirects=True`：自动跟随 302/307 到 CDN；没有手工读取 `Location`。
- 超时：connect 30s，read 3600s（不是总时长）；写入磁盘同步阻塞。
- 进度：只用 `content-length` 响应头；无 `content-length` 时不回调（`下载服务.py:49-56`）。
- 落盘：直接 `open(路径,"wb")` 写；没有临时文件/.part，失败会留下半文件。
- 校验：没有 ETag/MD5/大小比对；没有 Range/断点续传/多线程；没有重试。
- 并发：多选文件时 for 循环逐个下载（`文件浏览页.py:473-475`），无并发。
- 文件名：`os.path.join(保存目录, 项["名称"])`，名称来自服务端；未做路径穿越清洗（Rust 必须清洗）。
- `核心/下载/下载服务.py` 是另一份实现（60s 总超时、`httpx.stream` 全局函数），但 GUI 未引用；两处行为不一致。
### 6.3 302 / Range / 校验（待确认）
- 302：httpx 自动跟随；`signedURL` 可能直接是 CDN 或 302 到 CDN（❓抓包未给）。
- Range：服务端是否支持 `Range: bytes=`、是否返回 `206`+`Content-Range` 未验证；`网络客户端.流式GET` 接受任意头且只接受 200/206（`网络客户端.py:404-425`），但无调用者。
- 校验：未实现。Rust 建议下载后按 `fileSize` 校验；若后续拿到 MD5/gcid 再校验内容。

### 8.2 瞬时错误判定与重试矩阵
| 错误 | 是否瞬时 | 当前行为 | Rust 建议 |
|---|---|---|---|
| `ConnectError` / `ConnectTimeout` | 是 | 额外 3 次，0.5/1/2s | 保留 + 抖动 + 最多 3 次 |
| `ReadTimeout` / `WriteTimeout` / `PoolTimeout` | 不确定 | 不重试 | 对幂等 GET 可重试；上传不要盲目重试 |
| HTTP 401 | 会话过期 | 直接抛，不刷新 | refresh 后单次重试；再 401 引导登录 |
| HTTP 403/404/429/5xx | 视情况 | `raise_for_status`，不重试 | 429/5xx 可指数退避；403 检查 token/设备 |
| 业务 code 147 | 进行中 | 放行 → 轮询 | 保留 |
| 业务 code 156 | 秒传 | 正常分支 | 保留 |
| 业务 code 159 | 目录已存在 | 仅特定调用放行 | 保留；普通建目录也应识别 |
| 秒传检查失败 | 可选 | warning 后继续 | 继续，不要中断上传 |
| 任务 status 3/4/5 | 终态 | 抛错 | 明确文案 |
### 8.3 会话过期自愈
- 目前只有“按时间提前 5 分钟刷新”（§3.3）；**没有 401 自愈**。
- `网络客户端` 不持有令牌仓库引用，无法主动刷新；令牌由主窗口在登录时设置一次（`主界面.py:195-198`）。
- 令牌刷新失败 → `获取访问令牌()` 返回 None；但已建立的 `网络客户端.访问令牌` 仍是旧值，直到 UI 重新登录/重启（⚠️ 状态不一致）。
- Rust 建议：`TokenProvider` + `ApiClient` 解耦；请求前取有效 token；401 时 single-flight refresh 后重放一次；刷新失败发事件让 UI 跳登录。
### 8.4 风控/频控现状
- 短信：服务端盾 `captcha_token`（一次性、300s）、客户端 60s 倒计时；无服务端频控码映射。
- 业务 API：无签名/时间戳/nonce；仅 Bearer + 设备头 + traceparent。风控主要靠账号/设备/IP。
- 埋点：密钥为空，实际上报可能被忽略（`埋点上报.py:35`）。
- 上传：`capacity=30` 可能是并发通道配额（❓）；GUI 实际串行。
- 下载：直链由服务端签名，客户端不再带 token；泄露即临时可下载。
- 日志：DEBUG 级记录完整请求体（含文件名、URL、token 前 8 位）；生产应降级并脱敏。

### 9.2 ⚠️ 实测/源码备注（逐条）
1. **两套上传实现**：GUI 用单 PUT（`上传接口.py`），`分片上传.py` 未接线且依赖未安装的 oss2。Rust 不要照搬“大文件流式单 PUT”，应实现 multipart。
2. **`分片阈值`/`默认分片大小` 是误导名**：阈值只决定“一次性 bytes 还是流式生成器”，两者都是单 PUT。
3. **`Content-MD5` 从不发送**：签名里是空串；`res.md5` 只用于秒传判断。
4. **无 OSS 回调**：`callbackVar` 返回但被忽略；完成确认靠业务轮询。
5. **STS 不刷新**：`creds.expiration` 未解析；超长上传可能 403。
6. **`x-oss-user-agent` 参与签名**：Rust 若省略它，签名串也必须省略；不要只删头不改签名。
7. **`x-oss-date` 与 `Date` 二选一**：项目手工路径用 `x-oss-date` 填 Date 行；oss2 路径用 `Date`。混用会签名错。
8. **`Date` 不能用中文 locale 格式化**：必须 RFC1123 英文 GMT。
9. **objectPath 前导斜杠**：签名资源 `lstrip('/')`，URL 拼接 `f"{endpoint}/{objectPath}"`；若 objectPath 已带 `/` 会出现 `//`，❓服务端是否接受。
10. **ETag 引号**：`gcid` 去引号；`multipart/complete` 的 `parts.etag` 原样带引号（oss2 返回值）。
11. **秒传检查失败被吞**：不会阻止上传完成，但可能少一次秒传机会。
12. **`get_info_by_task_id` 没有总超时之外的退避**：固定 1s，服务端 147 持续 300s 即失败。
13. **令牌刷新无 401 触发**：过期后请求直接 401，UI 只显示错误。
14. **刷新 SDK 版本不一致**（9.0.2 vs 9.1.3）：可能被风控识别为异常客户端（❓）。
15. **扫码轮询不识别 OAuth 错误码**：`access_denied` 也会一直轮询到超时。
16. **令牌明文落盘**：`数据/令牌.json` 644；建议 Rust 用 keyring/0600。
17. **登录成功后不校验 token**：不调用 `/v1/user/me` 验证，直接认为成功。
18. **退出登录只删本地**：不撤销服务端 refresh_token。
19. **短信 `is_user=false` 仍可继续**：UI 只警告。
20. **埋点密钥为空**：签名可算但服务端大概率忽略；首版可不实现。
21. **下载无校验/无断点/无并发**：大文件失败即重来；文件名未清洗。
22. **列表不分页**：文件浏览只取前 50；回收站前 100；Rust 应补全。
23. **路径解析靠逐级列目录**：深路径 O(depth) 请求；同名目录取第一个。
24. **上传文件夹不处理 159**：目标已存在同名目录时可能整体失败。
25. **HTTP/2 关闭是 Python 兼容性 workaround**，不是协议要求；Rust 可协商 h2，但为降低差异建议先用 HTTP/1.1（reqwest 默认）。
26. **代理未显式配置**：httpx 会读环境变量；Rust reqwest 默认也读系统代理，行为接近。
27. **请求头非 ASCII 直接报错**：中文文件名只出现在 JSON body 或 multipart，不进 header；URL 中文会编码。
28. **`超时秒` 构造参数未使用**：实际固定 10/3600/3600/30。
29. **`接口.请求` 的 `params` 支持从未使用**：所有业务参数都在 JSON body。
30. **`任务接口.等待任务完成` 把异常吞掉继续轮询**：网络故障时可能空转到超时（`任务接口.py:58-60`）。

### 10.3 OSS 签名在 Rust 侧的实现
**V1 签名伪代码：**
```rust
fn oss_v1_authorization(
    method: &str, content_md5: &str, content_type: &str, date: &str,
    x_oss_headers: &BTreeMap<String, String>, // 已小写键
    bucket: &str, object_path: &str,
    ak: &str, sk: &str,
) -> String {
    let canonical_headers: String = x_oss_headers.iter()
        .filter(|(k, _)| k.starts_with("x-oss-"))
        .map(|(k, v)| format!("{}:{}\n", k.to_ascii_lowercase(), v.trim()))
        .collect();
    let resource = format!("/{}/{}", bucket, object_path.trim_start_matches('/'));
    let string_to_sign = format!(
        "{}\n{}\n{}\n{}\n{}{}",
        method, content_md5, content_type, date, canonical_headers, resource
    );
    let mut mac = Hmac::<Sha1>::new_from_slice(sk.as_bytes()).unwrap();
    mac.update(string_to_sign.as_bytes());
    let sig = BASE64_STANDARD.encode(mac.finalize().into_bytes());
    format!("OSS {}:{}", ak, sig)
}
```
**multipart 的 canonical resource：**
```rust
let resource = match subresource {
    None => format!("/{bucket}/{key}"),
    Some(("uploads", _)) => format!("/{bucket}/{key}?uploads"),
    Some(("part", n, upload_id)) =>
        format!("/{bucket}/{key}?partNumber={n}&uploadId={upload_id}"),
    Some(("complete", upload_id)) =>
        format!("/{bucket}/{key}?uploadId={upload_id}"),
};
```
**必须注意：**
1. `BTreeMap` 保证字典序；键统一小写；值 `trim()`；每行末尾 `\n`。
2. `Content-Type` 与实际发送完全一致（包括 `; charset=utf-8` 之类，若加）。
3. `Date`/`x-oss-date` 二选一；发送哪个，StringToSign 的 Date 行就用哪个值。
4. 不要发 `x-oss-user-agent`（简化签名）；如发，必须进 canonical headers。
5. 请求 URL 的 query 用 `url::Url::query_pairs_mut()` 编码；签名里的 `uploadId` 用原始值（不编码）。
6. `Content-MD5` 不发就传空串；不要留 `None` 导致格式变化。
7. ETag 解析：去 `"` 后作为 `gcid`；multipart complete 的 ETag 原样回传。
8. OSS 可能 200 + XML 错误：解析 XML 的 `<Error>`，不要只看状态码。
9. 时钟偏差：`x-oss-date` 与服务器差 >15 分钟会 403；启动时可用业务响应头 `Date` 校准（可选）。
10. 不要使用 V4：STS + V1 是项目验证过的组合；V4 需要 `x-oss-content-sha256`、credential scope、不同 canonical request。
**reqwest 配置建议：**
```rust
let client = reqwest::Client::builder()
    .user_agent(API_UA)
    .connect_timeout(Duration::from_secs(10))
    .read_timeout(Duration::from_secs(3600))
    .pool_max_idle_per_host(20)
    .http1_only()                 // 与 Python 行为对齐；可后续放开 h2
    .redirect(reqwest::redirect::Policy::limited(5))
    .build()?;
```
- 上传/下载用独立 Client 或同一 Client；下载 `Response::bytes_stream()` + `tokio::fs::File`。
- 上传分片并发用 `Semaphore(4)` + `JoinSet`；分片大小建议 8–16MiB（1MiB 对 OSS 偏小，请求数多）；最后一片可小于。
- 每个分片独立读文件：`tokio::fs::File::seek` + `take(len)`；或 `std::fs::File` + `spawn_blocking`。
- 失败时调用 `DeleteMultipartUpload`（`DELETE ?uploadId=`）清理（Python 未做，Rust 应补）。
### 10.4 兼容与迁移
- **令牌文件兼容**：保留中文键名读写，或一次性迁移；Rust 内部用英文结构体 + `serde(rename)`。
- **设备文件兼容**：保留 `设备ID`/`设备指纹`；不要重新生成 did，否则服务端视为新设备。
- **数据目录**：Python 用项目根 `数据/` 与 `~/.光鸭云盘/`；Rust 建议 `dirs::data_dir()/光鸭云盘/`，但迁移时读取旧路径。
- **时间**：令牌 `过期时间戳` 是 float 秒；JSON 反序列化用 `f64`，不要整数截断。
- **错误语义**：保留 `code/msg/HTTP status/request_id`；UI 文案可直接复用服务端 `msg`。
- **暗坑**：`clientId` 注入、`parentId=""` 根、`dirType=4`、`id` vs `shareId`、`dirName` vs `fileName`、全角冒号目录名。
