### 2.7 errno 检查

`网络客户端.py:340-376`：默认白名单是模块级不可变 `(0,)`；调用方必须逐次显式声明额外值（如 rapidupload 的 `(0,404)`）。仅当响应为 dict 且含 `errno` 才检查；消息优先 `errmsg`→`err_msg`→`show_msg`→默认。默认文案：`-6`=`未登录或登录已过期（errno:-6）`；`132`=`操作被风控拦截，需要人工完成短信验证（errno:132）`；其它=`接口返回异常`。`request_id` 取响应体；非 2xx 取响应头 `x-request-id`。

### 2.8 执行、错误包装、重试、自愈

`网络客户端.py:378-425` 的流程：

1. `_执行带重试()` 仅对 `httpx.ConnectError/ConnectTimeout` 重试（`:67-70`、`:129-166`）：3 次，0.5s→1s→2s。
2. `httpx.ReadTimeout` 包装为 `网络读超时`（`:201-210`、`:394-398`），**不重试**；长轮询据此继续。
3. `raw=True` 直接返回 `Response`，**跳过 2xx/JSON/errno 检查**（`:403-404`）；登录与 `/share/verify` 走此路径。
4. 非 2xx→`接口错误`；401 提示 `未登录或登录已过期`（`:406-413`）；JSON 解析失败→`接口错误("响应不是合法 JSON：...")`（`:415-422`）。
5. `errno:-6` 自愈：条件 `e.是未登录 and 需要认证 and 会话刷新器`；调用一次刷新，重建参数时剔除 `bdstoken`/`dp-logid`，重放一次（`:469-485`）。只补 bdstoken，不能续期 BDUSS/STOKEN。
- **接线的坑**：`界面/主界面.py:219-223` 用 `网络客户端()` 直接创建 UI 客户端，未传刷新器；`认证服务` 传入外部网络时也不补。因此 UI 侧“-6 自动补 bdstoken 重放”实际不生效。HTTP 401 也不会触发自愈（抛出的错误 `errno=None`）。
- 其它辅助：`账号请求()` 走 passport 且 `带业务头=False`（`:535-540`）；`原始PUT()` 可重试（`:542-550`）；`流式PUT()` 一次性、不重试（`:552-567`）；`流式GET()` 只接受 200/206、失败返回 None（`:569-593`）；`表单文件请求()` 把整文件读进内存再 multipart（`:495-533`），实际上传不用它。

### 3.4 换取 Cookie（BDUSS/STOKEN）

`换取会话()`（`登录服务.py:394-452`）：调用 ④；逐条解析 `response.headers.get_list("set-cookie")` 交给 `会话仓库.从cookie头列表提取()`（`:425-426`）；仓库仍无效时把 cookie jar 拼成 `k=v;...` 再解析（`:427-431`）；仍无效则抛错，并解析 `code`/`errInfo.no` 或正则 `"no"\s*:\s*"([^"]+)"`（`:432-448`）。

- **Set-Cookie 坑**：不能先 join 再按 `[,\n]` 切，`expires=Mon, 13-Sep-27` 的逗号会吃掉下一个 cookie 名；必须逐头解析，每个头只按第一个 `;` 取主体（`会话仓库.py:233-265`）。
- 只保存映射表五个名字：`BDUSS/BDUSS_BFESS/STOKEN/BAIDUID/BAIDUID_BFESS`（`会话仓库.py:41-47`）；代码不显式提取 `PANWEB`。
- **passport 域 vs pan 域**：代码不发 domain 级 Cookie，所有域共用同一显式 Cookie 头；passport 只负责 302 下发，pan 业务请求由默认客户端发。Cookie 域差异对客户端无影响。

### 3.5 建立 pan 域会话与子域种植

- ⑤ `建立网盘会话()`：`GET /v3/login/api/auth/?return_type=5&tpl=netdisk&u=https://pan.baidu.com/disk/main`，失败只告警（`登录服务.py:469-487`）。
- ⑥ `种植子域会话()`（`:440-467`）对 `pcs.baidu.com` 与 `pcsdata.baidu.com` 各一次：外层 `GET passport /v3/login/api/auth?return_type=3&tpl=netdisk&u=<目标>`，目标为各自的 `rest/2.0/pcs/file?method=plantcookie&source=pcs`。
- ⚠️ 该链会被 wappass 302/400 到 `Unsupported open api`；**失败不算登录失败、不要重试**（重试会反复被打回，日志出现 `_retry_=1`）。superfile2 实测只需 `BDUSS+STOKEN`，不依赖 plantcookie（`PLAN.md` §5.2 Q1c）。

### 3.6 登录后的 bdstoken / uk

`完成扫码登录()`（`登录服务.py:489-558`）：二维码→等待→换 Cookie→建立 pan 会话；若 `仓库.获取bdstoken()` 或 `获取uk()` 为空，**新建 base_url=pan 的客户端**（注入同一仓库）调 `认证服务.刷新会话()`（`:517-541`）；不能在本服务的 passport 客户端上取（该路径会被重定向到登录页 HTML，报“响应不是合法 JSON”）；最后子域种植，返回 `{方式:"扫码", uk, 种植子域, 会话}`。

`认证服务`（`认证服务.py`）端点：

| 方法 | 请求 | 关键点 |
|---|---|---|
| `取模板变量()` | `GET /api/gettemplatevariable?fields=["bdstoken","token","uk","isdocuser","servertime"]` | 会话引导入口；结果在 `result`；`bdstoken` 落库并回填 `uk`（`:43-66`） |
| `刷新会话()` | 同上 | 供网络层回调；**不得抛异常**，失败返回 False（`:68-79`） |
| `检查登录态()` | `GET /api/loginStatus?clienttype=1&channel=web&version=0` | 参数特例；`带渠道=False`；取 `login_info`（`:81-100`） |

### 3.7 会话文件读写、校验、刷新、登出

- 保存：先写 `会话.json.tmp`，`os.replace`，`chmod 0600`（`会话仓库.py:120-128`）；白名单键、忽略 `None`、每次覆盖 `更新时间`（`:192-202`）。
- 读取：JSON 失败或文件不存在→空会话，按未登录（`:107-116`）；**不校验有效性**。
- 校验：`是否有效() = (bduss or bduss_bfess) and stoken`（`:167-172`）。
- 刷新：没有 OAuth refresh，只能重新 `gettemplatevariable` 补 `bdstoken/uk`（`:209-211`）。
- 自愈：见 §2.8；只重放一次。
- Cookie 头导出顺序 `BDUSS; BDUSS_BFESS; STOKEN`（`:174-187`）。
- 从文本导入：`解析cookie文本()` 支持分号/换行、剥 `Cookie:` 前缀、按第一个 `=` 切（`:69-86`）；名字大小写不敏感，只收映射表五个（`:213-231`），至少命中一个，否则 `未在文本中找到 BDUSS / BDUSS_BFESS / STOKEN`（`:224-227`）。
- 从多个 `Set-Cookie` 提取：逐头解析，见 §3.4。
- 登出：`清空()` 清内存并删文件（`:277-289`）；UI 随后禁用页面并清 Tab（`界面/主界面.py:425-455`）。
- **UI 启动自检只查 `获取bduss()` 是否存在**，不查 STOKEN、不调 loginStatus（`界面/主界面.py:191-204`）；“有 BDUSS 无 STOKEN”会显示已登录但首个请求即 `-6`。Rust 应改为 `是否有效() && 取模板变量/loginStatus`。

### 3.8 其他登录方式

- **手工导入 Cookie（README 推荐，最可靠）**：UI 粘贴整行 Cookie（`界面/主界面.py:344-390`）；解析规则见上；导入后再校验 `是否有效()`，不满足提示“至少需要 BDUSS 与 STOKEN”（`:369-384`）。最小集 `BDUSS + STOKEN`，推荐 `BDUSS + BDUSS_BFESS + STOKEN`（`PLAN.md` §4.6）。
- **没有内置浏览器/WebView**：全项目 `WebEngine|QWeb` 命中 0；没有 `QWebEngineView`/Cookie 抓取。
- **没有 token/OAuth 登录**：无 `Authorization: Bearer`、无回调；`令牌.json` 是遗留（§1.3）。
- **没有短信/账号密码登录**（`界面/主界面.py:157`、`:346`）。仅扫码 + 手工 Cookie 两条路径。
- `设置访问令牌()` 是空兼容垫片（`网络客户端.py:262-268`），UI 仍在调用。

### 5.2 哈希算法与 MD5 双轨制

常量（`哈希计算器.py:34-39`）：`分片大小=4*1024*1024`（4194304）、`首片大小=256*1024`（262144）、`读块大小=2*1024*1024`。

两套表示（`哈希计算器.py:8-31`）：**纯净 MD5** 用于 `precreate.block_list`、`superfile2` 响应、`create.block_list`；**加密 MD5（展示态）** 用于 `/api/list`、`/api/filemetas`、`/api/create` 响应、缩略图 URL、`rapidupload` 的 `content-md5`/`slice-md5`。

官方 `_encryptMd5` 的 Python 实现（`:45-60`）：

```python
if not (32位纯小写hex): return e
i = e[8:16] + e[0:8] + e[24:32] + e[16:24]            # ① 4×8 重排
r = "".join(format(int(i[o],16) ^ (15 & o), "x") for o in range(32))  # ② XOR o%16
return r[:9] + chr(ord("g") + int(r[9],16)) + r[10:]  # ③ 第9位→g..v
```

逆运算 `解密md5()`（`:63-90`）：第 9 位若 `g..v` 减去 `ord("g")` 还原 hex，本身就是 hex 则保留；再 XOR 与反向重排（①②自逆）。各函数：`计算文件MD5()`（`:92-106`，整文件 2MiB 分块）、`计算首片MD5()`（`:108-110`，前 256KiB）、`计算分片MD5()`（`:112-149`，空文件返回 `[md5("")]`）、`计算全部哈希()`（`:151-215`，**单次读盘**返回 `{大小,整文件md5,首片md5,分片md5列表,分片数,整文件md5_加密,首片md5_加密}`）、`读偏移数据()`（`:217-220`）。

### 5.3 秒传（`/api/rapidupload`）

`秒传服务.py:84-155`：入参是**纯净** MD5，内部转加密态；`data_time=int(time.time())`；`data_offset` 是确定性公式（`:70-80`）：

```python
窗口 = 大小 - 262144 + 1
if 窗口 <= 1 or not uk: return 0
摘要 = md5(f"{uk}{content_md5_加密}{data_time}").hexdigest()
return int(摘要[:8],16) % 窗口
```

`data_content=base64(文件[offset:offset+262144])`；表单含 `path/content-length/content-md5/slice-md5/target_path/local_mtime/data_time/data_offset/data_content`，可选 `uploadid`（`:116-140`）。允许 `(0,404)`；404 正常未命中（`:142-148`）。**<256KiB 直接跳过秒传**（`:102-109`）：偏移公式分母为负，无法构造持有证明；实测 1KB 稳定 `errno:2`，300KB 起正常。其它实测：缺 `data_*`→`errno:2`；`data_content` 不匹配真实字节→`errno:2`（服务端确实校验）；`uploadid` 非必需；判定依据是 `content-md5`，与 `path` 无关（`:17-23`）。uk 先用会话，缺失临时 `GET /api/gettemplatevariable?fields=["uk"]`，失败 offset 退化为 0（`:47-67`）。

### 5.4 预创建与创建

- `预创建()`（`上传总调度.py:218-244`）：`POST /api/precreate?rtype=1`，form `path,autoinit=1,block_list=<本地纯净分片md5数组>,target_path,local_mtime`；必须返回 `uploadid`，否则 `RuntimeError`；响应的 `block_list` 是 `[0,1,2,...]` 占位，不可回传。`uploadid` 形如 `P1-<base64>` 或 `N1-<base64>`，实测恒 63 字符（PLAN §5.2）。
- `创建文件()`（`:246-270`）：`POST /api/create?isdir=0&rtype=1`，form `path,size,uploadid,block_list=<superfile2返回的md5列表>,target_path,local_mtime`；`block_list` 为空直接 `ValueError`，注释明确禁止用占位序号（`:248-252`）。
- **单分片文件的 `block_list[0]` 是整文件 MD5，不是首 256KiB**；后者只用于秒传 `slice-md5`（PLAN §5.2、`接口/上传接口.py:17-20`）。

### 5.5 上传域名解析（`locateupload`）

`分片上传.py:48-54`、`:84-160`：接入点 `GET https://d.pcs.baidu.com/rest/2.0/pcs/file?method=locateupload`，`带业务头=False`、`需要认证=False`、`raw=True`；实测**不带 Cookie** 也返回 `error_code:0`。取 `server` 列表，`server[0]` 为当前域名，把响应 `host`（如 `c.pcs.baidu.com`）追加到候选尾部（`:99-110`）；缓存 60s（`:126-146`）；解析失败且无缓存时临时兜底 `bddwd-cm01.pcs.baidu.com`（`:53-54`、`:117-120`）；失败切换 `server[1..]`，候选耗尽强制刷新（`:148-160`）。实测同账号同机 1 小时内出现 `bddwd-cm01`/`bdbl-cm01`/`xafj-cm11` 三个节点，**禁止硬编码**（PLAN §5.2.2）。

### 5.6 `superfile2` 协议（URL 拼接原文）

`分片上传.py:152-220`：

```python

    响应 = c.post(
        f"https://{域名}/rest/2.0/pcs/superfile2",

```

参数（`:161-173`）：`method=upload`、`logid=<base64>`、`app_id=250528`、`channel=chunlei`、`web=1`、`clienttype=0`、`path`、`uploadid`、`uploadsign=0`、`partseq=<从0开始>`、`dp-logid=<16+4>`。请求头：UA（§2.3 原文）、`Referer: https://pan.baidu.com/disk/main`、`Origin: https://pan.baidu.com`、`Accept: */*`、`Cookie` 三件套（`:174-182`）。单片超时 300s；失败最多 3 次，每次切域名并 `sleep(0.5*(尝试+1))`（`:184-220`）；HTTP 非 200、响应非 JSON、缺 `md5` 都算失败。响应 `md5` 是**服务端纯净 MD5**，必须收集给 create（`:205-209`、`:252`）。`partseq` 从 0 开始顺序上传，**没有并发**（`:247-255`）；片数 `max(1, ceil(size/4MiB))`，空文件也走 1 片（`:240`）。

### 5.7 远端目录、文件夹上传、记录

`确保远端目录()`（`上传总调度.py:154-199`）：先祖先再自身，逐级 `存在且是目录()`→`_创建目录()`；用 `/api/filemetas` 探存在性（`info` 空即不存在，`errno` 仍 0）；缓存 `_已建目录`。⚠️ 新建**已存在**目录不报错，会悄悄建出 `名字_20260914_045549` 副本（`:160-165`）；`.`/`..` 防御见 §4.1。

`上传文件夹()`（`:398-477`）：远端根=`父目录+"/"+本地文件夹名`（保留文件夹本身）；文件列表=`sorted(根.rglob("*") 中 is_file())`；相对父目录用 `relative_to(根).parent.parts` 过滤 `"."/".."/空段`。实测修过：①直接位于根下的文件 `Path("a.txt").parent=="."`，天真拼接会得 `/测试/.`，文件全丢进名为 `.` 的目录（百度居然接受）；②文件夹自身名字没拼进远端路径，内容被平铺。逐文件隔离，单文件失败只记日志+回调，不中断整批（`:463-470`）；批间隔 `0.05s` 仅为 UI 流畅（`:57-60`、`:472-475`）。

进度阶段与占比（`:43-52`）：计算哈希 0–15%、秒传 15–20%、预创建 20–25%、上传分片 25–90%、创建 90–100%；连续相同 `(阶段,百分比)` 去抖（`:272-300`）。**远端文件名直接取本地 `Path.name`，不做非法字符替换**；同名文件的上传覆盖/副本策略代码未显式处理，**待确认**。**上传完成校验只依赖 `create` 返回的 `errno/fs_id`，不回读文件、不比对 md5**；秒传命中也不返回 fs_id。**没有并发上传、没有跨会话断点续传**；文件串行、分片串行，失败只能整文件重来。上传记录格式见 §1.3。OSS/gcid/cid 已整体移除（`:12-20`、`项目配置.toml:14-15`），百度协议无这些概念。

## 6. 下载（`核心/下载/下载服务.py`）

- **取直链**：`GET https://pan.baidu.com/api/filemetas?target=["/path/file.bin"]&dlink=1&text=1&clienttype=0&app_id=250528&web=1&dp-logid=...`（`:95-123`，`带渠道=False`）；响应键 `info`，`dlink=info[0].dlink`。服务端已签好 `sign/expires`，客户端**不需要**自己算签名，这是绕开 `/api/download` 客户端签名难题的关键路线（PLAN §6.6 R10）。dlink 形如 `https://d.pcs.baidu.com/file/<md5>?fid=<uk>-250528-<fs_id>&rt=pr&sign=...&expires=8h&...`。
- **请求头**（`_下载请求头()` `:127-143`）：`User-Agent`（§2.3 原文）、`Referer: https://pan.baidu.com/`、`Accept: */*`、`Accept-Language: zh-CN,zh;q=0.9`、`Cookie: BDUSS; BDUSS_BFESS; STOKEN`，续传时加 `Range: bytes=<已有>-`。🔴 **必须带 Cookie**，否则 `HTTP 403 {"error_code":31045,"error_msg":"user not exists"}` 且不 302（`:9-20`、`:182-187`）。
- **重定向**：独立 `httpx.Client(timeout=下载超时, follow_redirects=True)`，从 `d.pcs.baidu.com` 302 到 `*.baidupcs.com`（`:180-181`）。超时 `connect 30/read 3600/write 30/pool 30`（`:51`）；读块 64KiB（`:48`、`:198`）。
- **Range/续传/进度**（`:147-210`）：目标已存在且 `断点续传=True` 时取已有字节数，`Range: bytes=<已有>-`、`ab` 追加；服务端返回 200（不支持 Range）则改 `wb` 从头（`:190-193`）。总大小优先取 `Content-Range: bytes a-b/total` 的 total，否则 `Content-Length + 已有`，未知 0（`:76-90`）。进度回调 `(已下载, 总大小)`，未知总大小传 0（`:195-205`）。403 单独包可读错误，其它 `httpx.HTTPError` 统一转 `接口错误`（`:182-207`）。
- **落盘命名**：`下载到目录()` 文件名取远端路径最后一段；`去重路径()` 已存在加 ` (1)`/` (2)`，最多 999，**绝不覆盖**（`:60-74`）；去重后必为新文件，调用 `下载到文件(..., 断点续传=False)`（`:212-235`）。
- **没有下载后 MD5 校验、没有分片并发、没有自动重试**；已有文件大于远端可能 416，未专门处理；目录打包未实现，UI 提示“目录暂不支持打包下载”（`界面/页面/文件浏览页.py:326-337`）。UI 多文件串行，单个失败不中断（`:343-367`）。

### 8.3 会话失效自愈与风控

自愈链：`请求→errno:-6→是未登录 && 需要认证（默认 true）&& 会话刷新器存在→刷新（GET gettemplatevariable）→成功则重建参数（剔除 bdstoken/dp-logid）→重放一次`；失败抛原错。只补 bdstoken，**不能续期 BDUSS/STOKEN**。UI 客户端未接刷新器（§2.8）。

风控：已知触发点为回收站彻底删除（132 + `verify_scene:2` + 短信）；客户端**无限流器**，README 建议 ≤5 req/s；现有低扰动措施为复刻 UA/Referer/Origin、每请求 `dp-logid`、superfile2 `logid`、分片/文件串行、批量间隔 0.05s、扫码 1.5s、任务 5s、转存 3s。禁止绕过验证码/伪造 authwidgetverify/自动重试 132。日志安全：`_形态()` 只输出长度+字符类别（`会话仓库.py:60-67`）；`_脱敏()` 抹掉 sign/qrcode/bduss/stoken/channel_id（`登录服务.py:102-108`）；压掉 httpx/httpcore/hpack/h11 DEBUG，只有 `DSH_HTTP_DEBUG=1` 才放开（`界面/主界面.py:28-42`）。

**认证/会话**

1. **STOKEN 硬性必需**：缺 STOKEN 即使 BDUSS 有效也 `-6`；`BDUSS` 与 `BDUSS_BFESS` 可互换，建议三者都带（`会话仓库.py:15-16`、PLAN §4.6）。
2. `getqrcode` **没有 `channel_id`、没有 base64 `qrcode`**；`imgurl` 省略 scheme 必须补 `https://`（`登录服务.py:168-172`）。
3. `channel_id` 的值就是 `sign`；传 `sign=` 得 `{"errno":-1}`，传 `channel_id=<sign>` 会挂起（`登录服务.py:20-22`）。
4. **扫码确认真实报文是 `status=0` 且带 `v`**，不是 `status=2`；状态从 1 回退到 0；一直等 2 会“手机确认了桌面没反应”（`登录服务.py:300-307`）。
5. unicast 未扫码约 30s 返回 `{"errno":1}`；长轮询 60s 读超时须当“尚未扫码”（`登录服务.py:71-73`、`:313-319`）。
6. **Set-Cookie 不能 join 后按逗号切**：`expires=Mon, 13-Sep-27` 会吃掉下一个 cookie 名，导致 BDUSS/STOKEN 静默丢失（`会话仓库.py:233-252`）。
7. **子域种植失败不是登录失败**：会被 wappass 302/400 到 `Unsupported open api`；不要重试（`登录服务.py:453-465`）。
8. **登录后必须主动取 bdstoken/uk**，且必须用 pan 域客户端；passport 上该路径会重定向到 HTML（`登录服务.py:517-541`）。
9. `/api/loginStatus` 参数特例 `clienttype=1&channel=web`（`认证服务.py:83-94`）。
10. `/api/user/getinfo` 缺 `need_boardinfo=1` 或 `user_list=[uk]` 报 `params error`，数据在 `records[0]`（`认证服务.py:117-142`）。

**文件/管理/回收站**

11. **判目录必须 `isdir==1`**；目录 `category` 恒 6、`size` 恒 0（`文件接口.py:58-61`、PLAN §3.1）。
12. **`filemetas`/`categorylist` 返回 `info`**，只有 `/api/list` 返回 `list`（`文件接口.py:13-21`）。
13. `/api/list` **不返回 total**，只能按“本页是否满”推断（`文件浏览页.py:275-277`）。
14. **`filelist` 结构随 opera 变**：delete 纯字符串数组；rename 带 id；move/copy 不带 id（`管理接口.py:14-28`）。
15. 删除 `async=2` 要拿 `taskid` 轮询；回收站还原 `taskid:0` 表示同步完成。
16. 回收站还原返回 **`faillist`**；彻底删除首次必 `132`+短信验证（`回收站接口.py:10-35`）。
17. **新建已存在远端目录不报错**，会建 `名字_20260914_xxxxxx` 副本（`上传总调度.py:160-165`）。
18. 百度对 `/测试/.` 不报错、默默建垃圾目录；上游必须过滤 `.`/`..`（`上传总调度.py:166-180`）。

**分享/任务**

19. 创建分享 **`pwd` 必需 4 位**；空串报 `pwd length param error`；响应不回显 `pwd`（`分享接口.py:12-20`、`:425-455`）。
20. 分享列表：`shareId`（大写 I）、`passwd`、`shortlink`（完整）vs `shorturl`（短码）；分页终止 `nextpage==0`（`分享接口.py:23-31`、`:167-200`）。
21. `sekey=unquote(randsk)`；`BDCLND` 必须显式带，否则 `/share/list` `-9`（`分享接口.py:95-113`、`:213-225`）。
22. 转存返回 **`task_id`（字符串）**，轮询参数名 **`taskid`**（`任务接口.py:17`、`分享接口.py:383-386`）。
23. `/share/surlinfoinrecord` 的 `sign` 来源未知，省略得 `errno:2`，功能标“暂不支持”（`分享接口.py:42-46`、`:524-568`）。

**上传/下载**

24. **上传域名动态**：同账号同机 1 小时内 `bddwd-cm01`→`bdbl-cm01`→`xafj-cm11`；必须 `locateupload` 的 `server[0]`，缓存 60s（`分片上传.py:21-30`、PLAN §5.2.2）。
25. **precreate 响应的 `block_list` 是 `[0,1,2,…]` 占位**，create 必须用 superfile2 返回的 md5（PLAN §5.2、`上传总调度.py:248-252`）。
26. **单分片文件的 `block_list[0]` 是整文件 MD5**，不是首 256KiB（后者仅秒传 `slice-md5`）（`接口/上传接口.py:17-20`）。
27. **<256KiB 无法秒传**：1KB 稳定 `errno:2`，300KB 起正常；代码直接跳过（`秒传服务.py:102-109`）。
28. 秒传 `data_offset` 是确定性公式；`data_content` 必须真实片段，服务端会校验（`秒传服务.py:17-23`、`:70-80`）。
29. **dlink 必须带 Cookie**，否则 403/31045 且不 302（`下载服务.py:9-20`）。
30. `filemetas?dlink=1` 能拿服务端签好的直链，**不需要客户端签名**；`/api/download` 的 56 字符 `sign` 算法未知且已废弃（PLAN §6.6/R10）。
31. 下载**没有并发分段、没有 MD5 校验、没有自动重试**；Range 只用于手动续传（`下载服务.py:147-210`）。
32. 上传**没有并发、没有跨会话断点续传**；单片失败 3 次+切域名（README 已知限制 7、`分片上传.py:184-220`）。

**环境/文档一致性**

33. **不要在 Python 3.14 + PySide6 下加定时 `gc.collect()`**：实测 38 文件批量传必崩于第 20+ 个；整堆一次 27–30ms；流式上传每文件约 0.7MiB，不需手工回收（`启动.py:9-17`）。
34. httpx/httpcore DEBUG 会打印 `Set-Cookie: BDUSS/STOKEN` 明文，必须压制（`界面/主界面.py:28-42`）。
35. UI 创建的 `网络客户端` 没有会话刷新器，`-6` 自动重放实际不发生（§2.8）。
36. **文档与代码冲突**：README 说扫码“尚未真机走通”，代码注释记录 2026-09-14 两次独立复现；PLAN §4.3 仍写 `qrcode`/`channel_id`/`status=2` 旧假设。以 `登录服务.py` 实现为准；扫码链路当前是否仍可用 **待确认**（本次禁止发请求）。
37. `令牌.json` 遗留不读（§1.3）；`追踪上下文.py` 死代码（§2.6）。
38. `界面/字段映射.py` 的 `分享类型映射`/`下载类型映射` 是空兼容表，对应旧骨架 shareType/downloadType（`分享接口.py:570-583`）。

### 10.3 编码/时间/签名注意

- 表单一律 `application/x-www-form-urlencoded`；JSON 只用于 `filelist/fidlist/fsidlist/block_list/target/shareid_list` 等字段值，不是整个 body。JSON 数组用紧凑分隔符；Rust `serde_json` 默认 UTF-8 不转义中文，等价 `ensure_ascii=False`。
- `data_content` 标准 base64（含 `+`/`/`/`=`）；`sekey/randsk` 是 URL 编码，必须 `percent_decode` 后使用；`BDCLND` 用原始 URL 编码值；`logid` 标准 base64 放 query 需 URL 编码；`dp-logid` 是纯数字。
- 路径参数直接作为 query/form 值，不要手工拼 URL；`target` 是 JSON 数组字符串；`content-length`/`content-md5`/`slice-md5` 字段名带连字符。
- 时间：服务端 `server_mtime/server_ctime/ctime/mtime` 是**秒级** epoch（`chrono::DateTime::from_timestamp(sec,0)`）；`tt/version/t` 是**毫秒级**；`local_mtime/data_time/上传记录时间` 是**秒级**；`dlink` 的 `expires=8h` 是字符串，不解析。
- 没有客户端 RSA/自定义签名；唯一“加密”是 MD5 展示态。`dlink` 的 `sign` 由服务端生成；`/api/download` 的 56 字符 `sign` 已废弃不要实现；`surlinfoinrecord` 的 `sign`（hex32）来源未知，**不要猜算法**；`sekey` 不是签名。
- 不要实现 OSS/gcid/cid，不要引入 `oss2`。

### 10.4 并发/重试/限流

- 连接层只重试连接失败；读超时不重试；`-6` 只重放一次；401 不重放。
- Rust 可把分片改并发（3–5）提升吞吐，但必须同 `uploadid`、按 `partseq` 顺序收集 md5 给 create、失败仍切域名；建议默认串行避免风控。
- 全局建议令牌桶 ≤5 req/s；132 永不重试；下载若要并发 Range 需自己切分合并（Python 版没有，属新增能力，需实测服务端稳定性）。
- 协议/文档不一致：扫码确认判据用“有令牌”；`/share/taskquery` 代码不带 bdstoken（文档带，待复核）；getinfo 必须两参数；loginStatus 参数特例；README/PLAN 旧描述以代码为准。

### 10.5 不建议迁移

`令牌.json`/OAuth 刷新（百度无 refresh_token）；`oss2`/gcid/cid；`追踪上下文.py`（死代码）；`设置访问令牌()`（空垫片）；`分享类型映射/下载类型映射`（旧骨架概念）；文件接口的 `NotImplementedError` 占位；自动“彻底删除”（132 风控）；本地 `qrcode` 生成库；Python 的定时 `gc.collect()` 纪律（Rust 无对应）。

### 10.6 验收用例

1. 会话：只含 BDUSS 判无效；BDUSS+STOKEN 有效；文件 0600；重启恢复。2. 扫码：`status=0+v` 识别确认；读超时继续轮询。3. 列表：根/中文/`/apps`/空目录/1000 条分页；目录 category=6 不误判。4. 管理：delete 字符串数组、rename 带 id、move/copy 不带 id、taskid 轮询。5. 秒传：<256KiB 跳过、≥256KiB 0/404、data_content 错误得 2。6. 分片：9MiB→3 片（4194304/4194304/1048576）；create 用服务端 md5；断网重试切域名。7. 下载：302 跟随；无 Cookie 403/31045；Range 206；200 从头覆盖；同名加 ` (1)`。8. 分享：4 位 pwd；创建响应无 pwd；列表取 passwd；verify→list→transfer；缺 BDCLND 得 -9。9. 回收站：restore 看 faillist；delete 只提示 132。10. 错误：-6 只重放一次；401 不重放；连接失败 3 次退避；读超时不重试。
